## 一、4 条事件"每个选项都要花钱"（`requireFullCash: true` + 扣钱）

| 事件 | 现有选项 |
| --- | --- |
| `d_price_jump` | 囤两罐 / 买一罐 |
| `d_bulk_rice` | 拼单三袋 / 自己扛一袋 |
| `d_scratch_card` | 凑到两百 / 只买清单 |
| `d_coupon_expiry` | 凑单一百 / 让它作废 |

**为什么必须改**：`requireFullCash: true` 的语义是"给不起就置灰"。
而这四条**两个**选项都是"要全款 + 扣钱"，于是一个兜里只剩几十块的玩家
点开事件只看到**两个灰按钮**，而事件还挂在屏幕上 —— 那不是难度，是卡住。
本项目有一条硬规矩：**任何界面都得有一条能走的路**（AGENTS.md 与 §4A）。

**怎么改（二选一，都行）**：

1. 加一个**第三个**"不花钱"的选项（转身走 / 今天不买了 / 先记下来），
   效果用 `visitLost: true` 或 `mood: +2` 这类"明确的不参与"；
2. 或者把其中一个选项改成**不买东西**的（例如"只买一袋"→"先看看价钱"）。

★ 注意**不要**把 `requireFullCash` 删掉来"绕过" —— 它的作用是让买不起的人
看到置灰而不是点了白点。要加的是**另一条路**，不是去掉限制。

## 二、6 条选项"给了货，但文案没提玩家拿到了什么"

| 事件 | 选项 | 现在的 outcome |
| --- | --- | --- |
| `d_bulk_rice` | 拼单三袋 | 你们四个人凑了一单。{spentCash}。 |
| `d_old_man_scale` | 买两把干菜 | 秤杆压得平平的。{spentCash}。 |
| `d_scratch_card` | 只买清单 | 账算得清清楚楚。{spentCash}。 |
| `d_price_freeze` | 今天就买 | 货架还有货。{spentCash}。 |
| `d_counter_short` | 低头结账 | 你数了两遍找零。{spentCash}。 |
| `d_coupon_expiry` | 凑单一百 | 券核掉了。{spentCash}。 |

**为什么必须改**：它们的 `effect` 里有 `grab`（真给货），而文案只交代了
"钱花了"，没交代"东西到手了"。这个项目**被玩家当场抓过这个 bug**，
原话是："我抢了东西买了东西……家里的东西并没有增长啊"。
所以有一条铁律：**文案承诺什么，`effect` 就必须给什么；反过来，
`effect` 真给了货，文案就必须提到拿到手。**

**怎么改**：在 outcome 里补一句"东西到手"的交代即可，别动 `effect`。
例：

```
d_bulk_rice「拼单三袋」
  现在：你们四个人凑了一单。{spentCash}。
  改成：你们四个人凑了一单，三袋米上了车。{spentCash}。
```

其余 5 条同理（"两把干菜装进袋子"、"按清单拿齐了"、"三袋主食搬上车"、
"一袋米拎在手上"、"凑够一百，东西到手"）。

## 不需要改的（写在这里，免得下次又有人去动它们）

- **"每条事件都要有一条 `visitLost` 的路"** —— 这条判据**已经改了**。
  §4A 要的是"能走开"，而全局出口是事件界面上常驻的「先不进去」
  （`ui/ShopScreen.ts` 的 `data-action="leave-event"` → `leaveShop`），
  它对每秒一条事件都有效。原来那条断言会逼着 20 条事件各加一个重复的
  "转身走"，那不是取舍，是噪音。详见 `src/systems/dayEvent.test.ts` 里的长注释。
- **`effect` 里写 `requireFullCash`** —— 这个**由入库脚本自动搬到选项层**了
  （生成提示词把它列在 effect 字段表里，而代码读的是选项层）。
  下次生成时**照旧写在 `effect` 里就行**，`scripts/merge-content.mjs`
  的 `fixPlacement` 会处理，并在报告里列出来。
  但**更省事的是以后把它写在 `options[]` 那一层**，那样连搬都不用搬。
- **选项用 `stamina: +2` 表示"歇一会儿/省下力气"** —— 这是可以的。
  判据已经与夜间事件对齐（"睡觉 +4 体力"算收益）。只有**单纯的代价**
  （`stamina: -4` 单独出现）才算"只有代价没有收获"。
