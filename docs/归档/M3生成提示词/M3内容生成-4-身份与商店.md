# 提示词 ④：玩家身份 + 商店点位（`kind: "identity"` / `kind: "shop"`）

> 先读 `M3内容生成-0-总纲.md` 与 `M3内容生成-_内容参照.md`。
> **目标：身份 10~16 个（现在 2 个）/ 商店点位 8~14 个（现在 3 个）。**

---

# 第一部分：玩家身份（`kind: "identity"`）

## 1. 身份是什么

身份决定**开局条件**：你有多少钱、车能装多少、一次能提多少、以及**一个天赋**。

**关键设计红线**（本项目反复强调的）：

> ## ★ 身份必须是**取舍**，不是强弱。

现有的两个身份就是照这个做的：

| 身份 | 钱 | 车载 | 单趟手提 | 天赋 |
| --- | --- | --- | --- | --- |
| **社区团购团长** | **900**（多） | 58kg | 16kg（少） | 主食与饮水便宜 15% |
| **加油站夜班员** | **780**（少） | 52kg | **22kg**（多） | 燃料与工具便宜 20% |

**"钱多 vs 车大"** —— 没有哪个更好，只有哪个更适合你的打法。
**你写的每一个身份都要能被这样一句话概括。**

---

## 2. 输出格式

```json
{
  "kind": "identity",
  "batch": "identity-01",
  "entries": [
    {
      "id": "nurse",
      "name": "夜班护士",
      "tagline": "在医院上夜班，见过太多人硬扛",
      "startCash": 820,
      "vehicleCapacity": 46,
      "carryLimit": 18,
      "perk": "职业习惯：医疗品便宜 25%",
      "perkRule": { "kind": "categoryDiscount", "categories": ["medicine"], "rate": 0.25 },
      "tier": 1,
      "decision": "医疗品便宜但车小 —— 把省下的钱压在药上，还是承认这局装不下太多东西"
    }
  ]
}
```

## 3. 字段规则

| 字段 | 规则 |
| --- | --- |
| `id` | 小写下划线，英文职业名（`nurse` / `delivery_driver` / `teacher`） |
| `name` | 中文职业名，**2~4 字** |
| `tagline` | 一句话人设，**≤20 字**。**不许煽情、不许台词腔**。要像"这个人是谁"的事实陈述 |
| `startCash` | **200 ~ 2000**。参照：14 天刚需约 700~810，所以 780~900 是"刚好够"的量级 |
| `vehicleCapacity` | 车载上限 kg/天，**10 ~ 90** |
| `carryLimit` | 单趟手提上限 kg，**5 ~ 40**，**必须 ≤ `vehicleCapacity`** |
| `perk` | 天赋一句话，**≤20 字** |
| `perkRule` | **见第 4 节 —— 这是最容易写错的地方** |
| `tier` | 1 = 开局可选 / 2 = 通关一次 / 3 = 特定成就解锁 / 4 = 稀有 |
| `decision` | 必填：**"它逼玩家用哪种打法？"** |

## 4. ★ `perkRule`：目前**只有一种**能用（这条请仔细读）

天赋的效果**必须由引擎实现**。现在引擎里只实现了**一种**规则：

```json
{ "kind": "categoryDiscount", "categories": ["medicine"], "rate": 0.25 }
```

意思是：**在你这里，这几个品类的物资便宜 `rate`**。

**别的天赋类型现在都跑不起来**（引擎不认识）。所以这一批请**只写这一种**，
把差异做在**打折的品类组合 + 强度**上：

| 可以做的变化 | 例子 |
| --- | --- |
| 打折的**品类组合** | 主食+饮水 / 燃料+工具 / 医疗+保暖 / 只打奢侈品 |
| 打折的**强度** `rate` | 0.1（小）/ 0.15 / 0.2 / 0.25 / 0.3（大） |
| 配合**开局数值** | 打折狠 → 现金给少点；打折小 → 现金给多点 |

**不许**写 `{ "kind": "somethingElse" }` —— 校验会因为引擎不支持而退回。

如果你想写别的天赋类型（例如"每天多 1 个行动点"），
**请在交付说明里单独列出来，标注"需要引擎支持"** —— 那是给开发者看的建议，不是现在能用的数据。

## 5. 数值平衡口径（**必须遵守，否则会破坏平衡**）

本项目有一组**全周期探针**（好档能不能活 14 天 / 乱档会不会倒），
身份数值失控会直接让探针失效。所以：

| 约束 | 理由 |
| --- | --- |
| `startCash` + 折扣省下的钱 ≈ **700 ~ 1100** 的"有效购买力" | 14 天刚需 700~810，太富裕就没有取舍了 |
| `vehicleCapacity` **不超过 90** | 它决定"一天能带回家多少"，太大 = 一次买完，行动点失去意义 |
| `carryLimit` **不超过 40** | 它决定"一趟搬多少"，太大 = 搬运的取舍消失 |
| **不许有"全面更强"的身份** | 每个身份都要有一项**明显更差** |

**自查办法**：拿你的新身份和现有两个比 ——
如果它在钱、车、手提、天赋**四项上都更好或持平**，那它就是个失衡身份，重写。

## 6. 身份的分档（`tier`）与解锁

- `tier: 1` → 开局就能选（**这一批请只出 tier 1**，2 个 → 共 6~8 个）
- `tier: 2` → 通关一次后解锁
- `tier: 3` → 特定成就解锁（例如"零求援撑满 14 天"）
- `tier: 4` → 稀有

★ 身份是 M3 元进程的**主要奖励之一**，所以它们的**玩法差异**比数量更重要：
16 个"钱多车大"的身份不如 10 个各有打法的身份。

**每一批请让 6~8 个身份覆盖不同的打法风格**（搬运 / 精算 / 交际 / 手工 / 谨慎），
并在交付说明里标出每个属于哪一类。

# 第二部分：商店点位（`kind: "shop"`）

## 7. 点位是什么

囤货期你出门采买，每天 3 个行动点，**1 点 = 进一个店门**。

> ## ★ 点位的唯一设计红线：**彼此不许重合。**
> 如果新店和超市卖一样的东西、一样的价钱，那它只是"多一次点击"。
> §6.2 的行动点设计**全靠点位之间存在取舍**才成立。

## 8. 输出格式

```json
{
  "kind": "shop",
  "batch": "shop-01",
  "entries": [
    {
      "id": "market",
      "name": "农贸市场",
      "blurb": "棚子底下还有几个摊。菜比超市新鲜，但没人给你装袋。",
      "priceFactor": 0.88,
      "actionCost": 2,
      "offers": [
        { "itemId": "rice_bag", "stock": 5 },
        { "itemId": "flour", "stock": 6 }
      ],
      "specialty": ["food", "dry"],
      "tier": 1,
      "decision": "多花一个行动点换更便宜的粮油，还是省下这点去药店"
    }
  ]
}
```

## 9. 字段规则

| 字段 | 规则 |
| --- | --- |
| `id` | 小写下划线。**不许用 `supermarket` / `pharmacy` / `hardware`**（已存在） |
| `name` | 中文名，**2~6 字** |
| `blurb` | 一句话点位描述，**≤30 字**。克制、不煽情。写**这个地方长什么样、有什么人** |
| `priceFactor` | **0.6 ~ 2.0**。`< 1` 比超市便宜 / `> 1` 更贵 |
| `offers` | **3 ~ 14 条** `{itemId, stock}`，`itemId` 必须真实存在，`stock` **1 ~ 30** |
| `specialty` | **1~3 个**品类或 tag：**这家店最划算的是什么**（必填，用于查重合） |
| `actionCost` | 可选，**1 ~ 3**。不写 = 1。**远的店花 2 点但更便宜**，那才是取舍 |
| `tier` | 1 = 开局可见 / 2 = 之后解锁 |
| `decision` | 必填：**"它逼玩家做什么决定？"** |

## 10. ★ 每家店都必须回答："我什么时候值得来？"

新店要**至少**满足下面一条，否则它没有存在意义：

| 差异化手段 | 例子 |
| --- | --- |
| **更便宜但更远**（`actionCost: 2` + `priceFactor < 1`） | 批发市场、郊区仓库 |
| **独家品类**（别处买不到） | 药店有处方药、五金店有燃料罐 |
| **库存更厚**（`stock` 高，适合一次买很多） | 仓储超市 |
| **灾后仍有货**（灾前冷清、灾后是唯一还开着的） | 社区小卖部 |
| **能换人情**（黑市、以物易物） | 黑市 |

**允许的建议点位**（你可以在这些方向里选，也可以自己写）：

```
农贸市场 / 粮油批发 / 仓储超市 / 社区小卖部 / 加油站
诊所 / 药房仓库 / 母婴店 / 宠物店 / 五金批发
学校 / 教堂 / 图书馆 / 老旧居民楼 / 黑市 / 郊区仓库
```

## 11. 交之前自查清单

**身份：**
- [ ] 每个身份都能用"**X 多 vs Y 少**"一句话概括
- [ ] **没有任何身份在四项上全面更强**
- [ ] `carryLimit ≤ vehicleCapacity`（校验会拦）
- [ ] `perkRule` **只用 `categoryDiscount`**
- [ ] `startCash` / `vehicleCapacity` / `carryLimit` 都在区间内
- [ ] `tagline` ≤20 字、无煽情、无台词腔

**商店：**
- [ ] 每家店都能回答"**我什么时候值得来**"（第 10 节五条里至少一条）
- [ ] `specialty` 与现有三家**不重合**（超市=粮油水、药店=药、五金=燃料工具）
- [ ] `offers` 里**没有一个不存在的 `itemId`**（校验会拦）
- [ ] `offers` 数量 3~14，`stock` 1~30
- [ ] `blurb` ≤30 字、克制

---

## 12. 最后：身份和点位是"开局"这件事的两个面

玩家点"开始"之前只做两个决定：**我是谁**、**我去哪儿**。

- **身份**回答"我擅长什么、我缺什么"；
- **点位**回答"我的钱花在哪儿、我要不要多跑一趟"。

**所以这两样加起来，就是"这一局会怎么玩"的全部预告。**
写完请自己读一遍：**读了之后，玩家会不会想"这局我试试另一条路"？**
会，就是好的。
