# 提示词 ①：物资（`kind: "item"`）

> 先读 `M3内容生成-0-总纲.md` 与 `M3内容生成-_内容参照.md`。这份只讲物资。
> **目标量：120 ~ 200 件**（现在 17 件）。分 4 批交，见第 4 节。

---

## 1. 你要做什么

给这个末日囤货游戏**扩充可囤的物资种类**。每一件物资都要：

1. 在**至少一种灾难**里有用（否则它不该存在）；
2. 和已有的 17 件**不重复**（不是"另一种罐头"，而是另一种**取舍**）；
3. 有**独立的图标键**（玩家要能在一屏几十格里一眼认出它）。

---

## 2. 输出格式

```json
{
  "kind": "item",
  "batch": "item-01",
  "entries": [
    {
      "id": "canned_corned_beef",
      "name": "午餐肉罐头",
      "category": "food",
      "icon": "can-corned-beef",
      "unitWeight": 0.4,
      "slotSize": 1,
      "stackLimit": 8,
      "perishable": false,
      "nutrition": { "food": 2, "comfort": 1 },
      "basePrice": 22,
      "tags": ["canned", "food", "treat"],
      "tier": 1,
      "decision": "它是少数能在零下不结冰的荤食，但比黄豆罐头贵一倍 —— 要不要为了口味花这笔钱",
      "note": "寒潮期的奢侈品食物：不结冰、能直接吃"
    }
  ]
}
```

### 字段逐条说明

| 字段 | 规则 |
| --- | --- |
| `id` | **小写 + 下划线**，英文/拼音，语义清晰。不许和现有 17 件重复 |
| `name` | 中文名，**2~6 字**。要像真货（"午餐肉罐头"✅ / "美味的肉类食品"❌） |
| `category` | 7 个之一：`food` / `water` / `medicine` / `fuel` / `warmth` / `tool` / `luxury` |
| `icon` | 图标键，**小写 + 连字符**。规则见第 3 节 |
| `unitWeight` | kg/件，**0.05 ~ 8**。参照参照表 §6.3 的量级 |
| `slotSize` | **1 / 2 / 4**（1=小件 / 2=大瓶 / 4=整袋） |
| `stackLimit` | 单槽堆叠上限，**1 ~ 20**。越稀缺的越小 |
| `perishable` | `true` 时**必须**给 `shelfLifeDays`（3 ~ 2000，天） |
| `nutrition` | `{food?, water?, health?, comfort?}`，每项 **0 ~ 3**。`luxury` 通常只给 `comfort` |
| `basePrice` | 元，**1 ~ 400**。参照：黄豆罐头 14、燃料罐 30、棉被 54 |
| `tags` | **1~4 个**，从参照表 §3 里选，可以新增但要克制（同一 tag 至少 3 件共用才有意义） |
| `tier` | **1 = 开局就有 / 2 = 玩几天出现 / 3 = 需要解锁 / 4 = 稀有**。这一批请**只出 tier 1~2** |
| `decision` | **一句话："它逼玩家做什么决定？"**（必填，见总纲 §1.3） |
| `note` | 一句话备注它**在哪种灾难里有不可替代的作用**（必填） |

---

## 3. 图标键 `icon` 的命名规则（**这条很容易做错**）

图标最终会被程序**参数化组合生成**（基础轮廓 × 变体轴），所以键名要
**可解析成"形状 + 变体"**，而不是随便一个词。

格式：`<形状>-<特征>[-<特征2>]`

| 形状词（基础轮廓） | 用于 |
| --- | --- |
| `can` | 罐头、铁罐 |
| `bottle` | 瓶子 |
| `jar` | 广口瓶、玻璃罐 |
| `bag` | 袋装、面粉、米 |
| `box` | 纸盒、药盒 |
| `carton` | 整箱、大件 |
| `tube` | 管状（药膏、胶水） |
| `tool` | 工具类 |
| `cloth` | 被褥、织物 |
| `device` | 电池、电器 |
| `misc` | 其他 |

**特征词**：材质（`tin` / `glass` / `plastic` / `paper`）、内容（`beans` / `water` / `fuel`）、
状态（`sealed` / `opened` / `dented`）。

**✅ 好的键**
```
can-corned-beef          ← 罐 + 午餐肉
bottle-glass-oil         ← 玻璃瓶 + 油
bag-flour-coarse         ← 袋 + 粗面粉
box-match                ← 盒 + 火柴
device-radio-hand        ← 手摇收音机
cloth-wool-blanket       ← 毛毯
```

**❌ 坏的键**
```
item_27                  ← 无意义
 yummy                    ← 不是形状 + 特征
can                      ← 缺特征，会和别的罐头撞
```

**每一件的 `icon` 必须与所有其他物资不同**（包括未来批次），所以特征词要够具体。

## 4. 分 4 批交（每批 25~50 件）

| 批次 | 主题 | 目标量 | 重点 |
| --- | --- | --- | --- |
| `item-01` | **主食与饮水** | 40 | 扩充到"能撑 14 天不重样"；引入**保质期长短的取舍**（罐头耐用但重、鲜食轻但会烂） |
| `item-02` | **医疗与工具** | 40 | 引入**"平时没用、出事救命"**的取舍；工具要能支撑别的品类（如炉子支撑燃料） |
| `item-03` | **燃料与保暖** | 30 | 寒潮核心。引入**"效率差异"**（同样取暖，煤油 vs 木炭 vs 电热毯的代价不同） |
| `item-04` | **奢侈品与纪念物** | 40 | **只进图鉴与心情**，是"人味"那一层。这是最容易写出好东西也最容易写废的一批 |

### 4.1 每批都要制造的"取舍类型"

**不要只扩充数量，要扩充取舍。** 每批至少覆盖下面几类，并在交付说明里标出分布：

| 取舍类型 | 例子 |
| --- | --- |
| **耐用 vs 轻便** | 罐头（2 年保质 / 0.4kg）vs 鲜食（3 天 / 0.2kg） |
| **大件 vs 小件** | 整袋米（8kg / 一次占 2 格）vs 速食（轻 / 但吃不饱） |
| **专精 vs 通用** | 专业药品 vs 万金油绷带 |
| **现在贵 vs 以后更贵** | 燃料（灾前 30，灾后翻倍） |
| **自用 vs 换人情** | 一条烟（自己不抽，但能换东西） |
| **有用 vs 想留** | 一本画册（不顶饿，但心情 +） |

## 5. 数值自查（交之前逐条对一遍）

- `unitWeight` 与 `stackLimit` 是否**互相合理**？
  （一袋 8kg 的米 `stackLimit` 不可能是 20 —— 那是 160kg）
- `basePrice` 与品类是否**合理**？
  （一罐饮料 400 元 ❌；奢侈品里 200 元的纪念物 ✅）
- `nutrition` 是否**与文案一致**？
  （叫"压缩饼干"就该 `food: 3`；叫"一块糖"就该 `food: 1, comfort: 2`）
- `perishable: true` 的**有没有给 `shelfLifeDays`**？（校验会拦）
- **同一批里有没有两件物资做的是同一件事**？（那是换皮，不是扩充）

---

## 6. 一次性交多少 / 怎么交

- 一批 **25~50 条**，一个文件，命名 `item-01.json`
- JSON 之前用 ≤3 行说明：条数 / **取舍类型分布** / 你认为最弱的一条
- **先把 `item-01` 交掉等确认**，再开 `item-02` ——
  第一批会被用来看你的口径对不对，口径对了后面才快

---

## 7. 最后：物资的价值不在数值，在"它替你说了什么"

这个游戏里物资是**叙事的载体**。一罐"过期的婴儿奶粉"比"高级营养剂"好一百倍 ——
因为前者让玩家自己想到了一个故事，而后者什么都没说。

**优先写"有来历的东西"**：别人送的、捡的、留着没舍得用的、本来准备送人结果没送出去的。

奢侈品那一批（`item-04`）尤其是这样。那 40 件不是数值，是这个游戏里唯一允许"没用"的地方 ——
**请把它们写得值得留下来。**
