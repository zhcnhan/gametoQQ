# 《囤货末世》内容生成 · 总纲（四份提示词共用）

> 这份是**给生成模型的**。你要产出的是**纯数据**，不是代码、不是文档。
> 配套的 4 份分册：**物资 / 事件 / 灾难 / 身份与商店**。
> 每份都能独立使用，但你生成的任何东西都要过下面第 4 节的"机器校验"。

---

## 0. 这是什么游戏（30 秒）

《囤货末世》是一个**手机竖屏 H5 的末日囤货整理模拟**。玩法是：

1. **囤货期（D-7 → D-Day，7 天）**：灾难要来，你出门采买、把东西搬回家、**整理上架**。
   每天 3 个行动点，1 点 = 进一个店门。
2. **生存期（D+1 → D+14）**：寒潮登陆，你靠囤的东西撑过去。四维是**健康 / 心情 / 体力 / 庇护所**。
3. **核心爽点是"整理"**：把物资拖到货架上、贴一张分区胶带、按临期优先排序。
   **整理得好 = 体力省 = 活下来。**

**调性**：末日手账。克制、冷静、不煽情、不玩梗。
参考的是《苏丹的游戏》的纸质卡片 + 黑白漫画墨与网点。
**文案是第一人称的观察，不是台词。**

## 1. 你的产出格式（**唯一要求，违反则全部退回**）

### 1.1 输出一个 JSON 对象

```json
{
  "kind": "<内容类型>",
  "tier": "<批次说明，纯注释用>",
  "batch": "<这一批的编号，例如 item-01>",
  "entries": []
}
```

- `kind` 只能是：`item` / `nightEvent` / `dayEvent` / `emergency` / `disaster` / `identity` / `shop` / `helpRequest`
- `entries` 是内容数组，**每一条都必须自带 `id` 与 `tier`**
- **不要写任何解释、不要写 Markdown 代码块以外的文字、不要写代码。**
  你可以在 JSON 之前用 ≤3 行说明这一批的思路，除此之外**只有 JSON**。

### 1.2 硬性禁令

| 禁止 | 说明 |
| --- | --- |
| ❌ 输出 TypeScript / JavaScript | 只要 JSON |
| ❌ 引用不存在的物资 id | 只能用 `_内容参照.md` 里列出的 id，或你在**同一次交付里**新定义的（新物资要单独成批先交） |
| ❌ 破折号 `——` | 正文里不许出现，这是这个项目的硬规矩 |
| ❌ 天气/物件拟人 | 不许"风在哭""冰箱记得"；**只报温度与事实**（"-27°C。水管冻裂了。"） |
| ❌ 环境有"记性" | 不许"上次的事人家还记得""又见面了"这类 |
| ❌ 台词腔 | 不许"哼，你也有今天"；NPC 的话要转述，不要引号对白 |
| ❌ 煽情词 | 不许"绝望""撕心裂肺""泪水" |
| ❌ 解释性括号 | 不许"（这意味着……）" |
| ❌ 重复 | 同一批里不许有两条"逼玩家做同一个决定"的内容（见第 3 节） |

### 1.3 每条内容都必须有一句 **`decision`**

**每条 `entries[]` 里都要加一个 `decision` 字段**，用一句话说清：

> **"它逼玩家做什么决定？"**

例：`"decision": "用掉今天最后一个行动点去补燃料，还是回家把已有的东西理好"`

**没有 `decision` 的条目直接退回。** 这是本项目判断"内容有没有价值"的唯一标准 ——
一条不逼玩家做决定的事件，只是一段读起来还行的文字。

## 2. 文案纪律（这是本项目的风格底线）

### 2.1 三条铁律

1. **只写看得见的事**。温度、声音、气味、手上的重量。不写心理活动。
2. **1~2 句**。第 3 句开始就是多余的。
3. **玩家的处境由数字表达，不由形容词表达**。写"你还有 3 天"，不写"你陷入了绝境"。

### 2.2 好的例子 vs 坏的例子

**✅ 好（克制、具体、有信息）**
```
"-27°C。楼下水管冻裂了，楼道里结了一层冰。"
"货架空了七成。收银台前排着二十几个人，没人说话。"
"你把最后一罐燃料搬进屋，手上的皮粘在把手上。"
```

**❌ 坏（拟人 / 煽情 / 台词腔 / 有记性 / 破折号）**
```
"寒风在耳边哭泣，仿佛在诉说着末日的绝望。"        ← 拟人 + 煽情
"上次的事，人家还记得呢。"                      ← 环境有记性
"王阿姨冷笑：哼，囤盐有什么用？"                  ← 台词腔
"物资所剩无几——你该怎么办？"                    ← 破折号 + 空洞
"你感到一阵莫名的不安。"                        ← 心理活动，无信息
```

### 2.3 术语表（**必须用这套词，不要自己造**）

| 用 | 不用 |
| --- | --- |
| 物资 / 件 | 物品 / 道具 / 装备 |
| 货架 / 格子 | 架子 / 槽位 / 背包格 |
| 分区（胶带） | 标签 / 分类系统 |
| 待拆的箱子 | 盲盒 / 包裹 |
| 顺手位（门口那块） | 快捷栏 |
| 四维：健康 / 心情 / 体力 / 庇护所 | HP / MP / SAN |
| 囤货期 / 生存期 / D-Day / D+3 | 前期 / 后期 / 第 0 天 |
| 点位（超市、药店……） | 地图 / 副本 / 商店界面 |

## 3. "不许重复"是什么意思（本项目的验收核心）

**两条内容重复，不是指文字像，而是指"它们逼玩家做同一个决定"。**

举例：

```
❌ 重复（同一个决定：要不要多买一箱水）
  "超市的水只剩两排了。"          → 决定：现在多买水，还是等明天
  "货架上的矿泉水被人搬空了。"     → 决定：现在多买水，还是等明天

✅ 不重复（三个不同的决定）
  "超市的水只剩两排了。"          → 决定：现在多买水，还是等明天
  "收银台只收现金，不找零。"       → 决定：要不要为了凑整多拿一件
  "有人把整箱水堆在门口，没人看着。" → 决定：拿（背上重量）还是不拿（心安）
```

**一批里，"同一个决定"最多出现 5 次。** 交之前请自己归类数一遍，把分类结果写在
JSON 之前的说明里（例如：`本批 20 条：资源取舍 5 / 人际 4 / 环境 4 / 身体 3 / 运气 4`）。

## 4. 机器校验（交之前请自己先过一遍）

你的产出会被这个脚本检查，**任何一条不合格，整批退回**：

```bash
node scripts/check-content.mjs <你的文件>.json    # 校验
node scripts/check-content.mjs --explain          # 打印每种内容的最新要求
```

它检查 5 类：

1. **重复 id**（批内、以及与现有内容表冲突）
2. **字段缺失或类型不对**
3. **引用悬空**（`itemId` / `boxDefId` / `category` / `shopId` 必须真实存在）
4. **可达性**（不能是"写了但永远出不来"的内容）
5. **数值区间**（价格 / 重量 / 保质期 / label 长度等）

### 4.1 最重要的一条校验：**每个选项必须有真实收获**

事件类内容的每个 `option`，**必须让玩家的净收益为正**：

- ✅ 算收获：拿到货（`grab` / `boxDefId`）、现金增加、四维增加（**包括"睡觉 +4 体力"**）
- ❌ 不算收获：单纯扣体力/心情、只改商店库存、只加限购

**为什么这条是硬的**：这个项目真的犯过这个错 —— 有一条事件选项的文案写着
"你把架子上的主食拿掉一半"，而效果里**根本没有给货**。玩家的原话是
*"我抢了东西买了东西……家里的东西并没有增长啊"*。

**所以还有一条配套的铁律**：

> ## ★ 文案承诺什么，`effect` 就必须给什么。
> 文案说"你拿到了两袋米"，`effect` 里就必须有 `grab` 或 `boxDefId`。
> 文案说"你结了账"，`effect` 里就必须有 `cash`。
> **说"拿"就必须真给，说"买"就必须真有收支。**

## 5. 工作流（你是个 agent，请按这个来）

1. **先读 `_内容参照.md`**：那里有现有的全部物资 id、品类、tag、箱型、点位。
2. **先出一批小的（10~20 条）**，自己对照第 3 节分类、第 4 节自查。
3. **交付格式**：一批一个文件，命名 `item-01.json`、`night-01.json` 这样。
4. **每批交之前，在 JSON 之前用 ≤3 行说明**：
   - 这一批的编号与条数
   - **决定分类统计**（见第 3 节）
   - 你认为这一批里**最弱的一条**是哪条、为什么（这句很有用，别省）
5. **不要一次交几百条**。一批 20~40 条，质量比数量重要得多 ——
   500 条同质内容对这个游戏的伤害大于帮助。

## 6. 这个项目最看重什么（如果你只记一件事）

> **内容的价值 = 它逼玩家做的那个决定有多难。**

一条"涨了 15% 物价"的事件，如果玩家没有别的选择，那它只是噪音。
一条"今天物价涨了 15%，但街角那家店还没调价，去那儿要多花一个行动点"的事件，
才是这个游戏要的东西。

**先想清楚那个决定，再写文案。** 不是反过来。
