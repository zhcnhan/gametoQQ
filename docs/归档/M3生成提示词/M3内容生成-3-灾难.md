# 提示词 ③：灾难（`kind: "disaster"`）· 一百多场 · 多维度

> 先读 `M3内容生成-0-总纲.md` 与 `M3内容生成-_内容参照.md`。
> **目标量：112 ~ 116 场**（现在 1 场：寒潮）。**这是四份提示词里最难、也最重要的一份。**

---

## 0. 先理解灾难在这个游戏里是什么

灾难**不是敌人**，也**不是难度档位**。它是：

> **一次对所有系统的重新定价。**

同一套物资、同一套整理玩法，换一场灾难就换一种"什么最值钱、什么最没用、日子怎么过"。
**灾难是唯一能同时改动十几个系统的东西** —— 这就是它值钱的地方，也是这份提示词的全部难点。

### 0.1 现有的唯一一场：寒潮（读它，然后**不要重复它**）

| 维度 | 寒潮的取值 |
| --- | --- |
| 外界温度 | D-7 是 +6°C，D-Day 掉到 -18°C，D+14 压到 **-36°C** |
| 腐坏速度 | **0.5**（外面就是冷库，东西反而更耐放） |
| 每日消耗 | 燃料 +2（多烧一档） |
| 刚需品类 | 燃料、保暖 |
| 压力轴 | **热量**：外面比屋里冷得多，你要烧东西 |

**注意 `spoilRate: 0.5`** —— 寒潮让食物更耐放。这个反直觉的设计很重要：
它意味着**寒潮局里囤鲜食是划算的**，而热浪局里恰恰相反。
**每一场灾难都要有这样一个"反直觉但说得通"的侧面。**

## 1. ★★ 核心要求：每场灾难必须**同时改动多个维度**

用户的原话：

> "灾难是要跟其他所有一切做衔接的……寒流肯定是棉被之类最贵重、保暖的燃料等，
> 但是物品腐坏速度降低；炎热天气那就贼拉高。诸如此类都是**多角度全方位影响**的。
> 我说的都是最简单的，**有一些是要非常复杂的**。"

### 1.1 全部 17 个影响维度（**你的主战场**）

| # | 维度 | JSON 字段 | 玩家感受到什么 | 层级 |
| --- | --- | --- | --- | --- |
| 1 | 每日消耗 | `dailyDrain` | 今天要烧/喝/吃多少 | L1 |
| 2 | 腐坏速度 | `spoilRate` | 东西能放多久 | L1 |
| 3 | 刚需排序 | `priorityCategories` | 什么最值钱、顺手位放什么 | L1 |
| 4 | 外界温度 | `temperatures` | "外面 vs 屋里"那一栏 | L1 |
| 5 | 庇护所衰减 | `shelterDecayPerDay` | 屋子每天坏多少（漏风/进水/裂缝） | **L2** |
| 6 | 休息效率 | `restEfficiency` | 睡觉能回多少体力 | **L2** |
| 7 | 搬运惩罚 | `carryFactor` | 一趟能提多少（高温 / 缺氧 / 风雪） | **L2** |
| 8 | 行动点修正 | `actionPointDelta` | 今天有几个行动点 | **L2** |
| 9 | 商店供应 | `shopSupplyFactor` / `closedShopIds` | 门还开不开、货还全不全 | **L2** |
| 10 | 物价加成 | `priceSurcharge` | 这一场本来就贵 | **L2** |
| 11 | 事件池权重 | `eventPoolWeights` | 碰上什么事（寒潮多"冷"、骚乱多"人"） | **L2** |
| 12 | NPC 行为 | `npcVisitFactor` / `npcPoolIds` | 还有没有人来敲门、来的是什么人 | **L2** |
| 13 | 品类效率 | `categoryEfficiency` | 同样的东西在这一场更管用 / 更不管用 | L3 |
| 14 | 空间限制 | `capacityFactor` / `unusableShelfIds` | 有些地方用不了了（进水 / 结冰 / 塌了） | L3 |
| 15 | 健康风险 | `healthRiskPerDay` | 硬扛的代价（不见血地掉） | L3 |
| 16 | 分数口径 | `scoreWeights` | 这一局的评分看什么 | L3 |
| 17 | 独有机制 | `specialMechanics` | 这一场独有的规则（口罩 / 宵禁 / 隔离） | L4 |

### 1.2 ★ 每场灾难的**最低要求**（硬性）

> **一场灾难至少改动 6 个维度，其中至少 1 个是"反直觉"的。**

| 层级 | 要求 | 场次配额 |
| --- | --- | --- |
| **L2 标准** | 6~9 个维度，含 1 个反直觉 | **70 场**（主力） |
| **L3 复杂** | 10~14 个维度，至少改一个"玩法级"的（13~16） | **34 场** |
| **L4 独有** | 15+ 维度，且带一个**这一场专属的机制** | **10~12 场** |

### 1.3 什么叫"反直觉的侧面"（**这是内容质量的试金石**）

一个和"这场灾难很糟"直接推导出来的效果，只是数字；一个**没人会立刻想到**、
但想通之后觉得"确实如此"的效果，才是好设计。

| 灾难 | 直觉效果 | ★ 反直觉侧面（要写这种） |
| --- | --- | --- |
| 寒潮 | 燃料烧得快、外面很冷 | **东西反而更耐放**（外面是冷库） |
| 热浪 | 水喝得多、容易中暑 | **冰箱反而成了耗电大户**，且**夜里凉快时才是活动时间** |
| 洪水 | 出行困难、怕水的东西毁了 | **饮用水变多但都不能喝**（水源污染 + 净水能力跟不上） |
| 大停电 | 照明没了、电梯停了 | **冷藏的东西必须在两天内吃掉** —— 从"存货"变成"限期任务" |
| 疫情 | 生病风险高、药品刚需 | **邻居反而更愿意换东西**（谁都怕出门，人情变值钱） |
| 骚乱 | 危险、物资被抢 | **奢侈品反而最安全**（没人抢一本画册），能换到硬通货 |
| 沙暴 | 不能出门、呼吸难受 | **灰尘进到屋里**，整理好的货架要重新擦一遍（整理本身变成本） |
| 余震 | 房子危险 | **"轻的东西放高处"这条常识反转了** —— 掉下来会砸人 |

**每一场都要有这样一条。** 交付时请在 `notes` 里**单独写出来**，见第 3 节。

## 2. 一百多场怎么组织：**家族 × 强度 × 变体**（不是 100 份手写）

```
灾难家族（机制内核）          强度档              变体（换皮 + 换细节）
 ① 温度：冷 / 热              轻 · 中 · 重 · 极    地名 / 季节 / 前兆 / 组合
 ② 水：洪水 / 缺水 / 污染
 ③ 结构：地震 / 塌方 / 停电
 ④ 生物：疫情 / 虫害 / 霉变
 ⑤ 社会：骚乱 / 宵禁 / 断供
 ⑥ 空气：沙暴 / 毒雾 / 烟霾
 ⑦ 组合：两种同时来
```

- **家族决定机制内核**（它改哪几个维度、怎么改）；
- **强度档决定数值深浅**（轻 = 前 7 天还有余裕；极 = D-Day 当天就吃紧）；
- **变体决定叙事**（同样"冷"，可以是寒潮 / 雪灾 / 化工厂泄漏导致的降温）。

### 2.1 场次分配（合计 112~116 场）

| 家族 | 场次 | L2 | L3 | L4 |
| --- | --- | --- | --- | --- |
| 温度 | 24 | 16 | 6 | 2 |
| 水 | 16 | 10 | 5 | 1 |
| 结构 | 16 | 10 | 4 | 2 |
| 生物 | 16 | 10 | 5 | 1 |
| 社会 | 16 | 10 | 5 | 1 |
| 空气 | 12 | 8 | 3 | 1 |
| **组合** | 12~16 | 6 | 6 | 2~4 |
| **合计** | **112~116** | 70 | 34 | 10~12 |

### 2.2 ★ 组合家族是性价比最高的一类

它**不需要新机制**，只需要"两个已验证的内核同时生效"。而它能造出这个游戏最好的体验：

```
"寒潮 + 大停电"  = 没有取暖的寒潮（燃料还在，但炉子不转了）
"热浪 + 断供"    = 水喝得最多的时候，水最贵
"洪水 + 疫情"    = 不能出门，但必须去看医生
"宵禁 + 骚乱"    = 白天不能出门，夜里更不敢出门
```

### 2.3 ★★ 同质化的机械验收（**这条会由程序检查**）

> **任意两场灾难，如果只在前 4 个维度（`dailyDrain` / `spoilRate` /
> `priorityCategories` / `temperatures`）上不同，就必须合并或重写。**

这就是"一百多场"不退化成"十二种灾难 × 八种数值"的保证。
**交之前请自己两两比一遍**，并在交付说明里写明：你这一批**新增了哪个维度的用法**。

### 3.1 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` | ✅ | 小写下划线，语义清晰（`heat_wave` / `flood_urban` / `blackout_winter`） |
| `name` | ✅ | **2~4 字**（"热浪" / "大停电" / "沙暴"） |
| `family` | ✅ | 7 个家族之一：温度 / 水 / 结构 / 生物 / 社会 / 空气 / 组合 |
| `level` | ✅ | `L2` / `L3` / `L4`，见第 1.2 节的最低维度数 |
| `tier` | ✅ | 解锁层级：1 = 开局（寒潮）/ 2 = 通关一次 / 3 = 图鉴进度 / 4 = 成就解锁 |
| `axis` | ✅ | 一句话：**这一场的压力轴是什么** |
| `temperatures` | ✅ | **至少给这 8 个关键日**：`-7, -4, -1, 0, 3, 7, 11, 14`（中间日可省略，程序会插值取最近的一档） |
| `spoilRate` | ✅ | `< 1` 更耐放 / `> 1` 加速腐坏 / `= 1` 不动 |
| `dailyDrain` | ✅ | 每日额外消耗，只用 7 个品类 |
| `priorityCategories` | ✅ | **1~3 个** |
| `windowScene` | ✅ | 窗外渲染 key，小写连字符 |
| **`shelterDecayPerDay`** | L2+ | 屋子每天掉多少庇护所（负数=变坏），**-0.5 ~ -4** |
| **`restEfficiency`** | L2+ | 睡觉回复效率乘数，**0.4 ~ 1.2**（>1 = 这一场睡得更香） |
| **`carryFactor`** | L2+ | 单趟搬运乘数，**0.5 ~ 1.0** |
| **`actionPointDelta`** | L2+ | 行动点增减，**-1 ~ +1** |
| **`shopSupplyFactor`** | L2+ | 商店库存乘数，**0.4 ~ 1.0** |
| **`closedShopIds`** | L2+ | 这一场关掉的门（数组，可空） |
| **`priceSurcharge`** | L2+ | 全局涨价，**0 ~ 0.8**（`0.25` = 贵 25%） |
| **`eventPoolWeights`** | L2+ | 事件池权重 `{标签: 倍数}` |
| **`npcVisitFactor`** | L2+ | 有人来敲门的概率乘数，**0 ~ 1.5** |
| **`categoryEfficiency`** | L3+ | `{品类: 乘数}`：同样的东西在这里更/更不管用，**0.5 ~ 1.5** |
| **`capacityFactor`** | L3+ | 可用空间乘数，**0.5 ~ 1.0** |
| **`unusableShelfIds`** | L3+ | 这一场用不了的货架 |
| **`healthRiskPerDay`** | L3+ | 每天硬扛的健康代价，**0 ~ 3** |
| **`scoreWeights`** | L3+ | 评分口径 `{organize, survival, variety}` |
| **`specialMechanics`** | L4 | 独有机制的 key 数组（**需要引擎支持，见第 6 节**） |
| `calendar` | ✅ | **正好 22 天**：`day` 从 **-7 连续到 +14**，每天 `{day, severity, hint}` |
| **`counterIntuitive`** | ✅ | **这一场那条反直觉的侧面**（见第 1.3 节），写成一句话 |
| **`decisions`** | ✅ | **2~4 条**："它逼玩家做什么决定"（必须互不重复） |
| `notes` | ✅ | 写明**本场用到了哪些维度编号**（便于查同质化，便于后续场次避开） |

### 3.2 `calendar` 的写法（22 天 × 112 场 = 2464 条文案，是这份活的主体）

| 规则 | 说明 |
| --- | --- |
| **1 句话，≤30 字** | 先知日历上的一行 |
| **只报事实与数字** | 温度 / 水位 / 湿度 / 能见度 / 天数 / 声响 |
| **D-7 ~ D-1 = 预告口气** | 灾难还没来，语气是观察与准备 |
| **D-Day = 登陆** | `severity` 跳到 1.0 附近，语气转成当下 |
| **D+1 ~ D+14 = 处境** | 语气是"撑"。最后两三天可以留一句余味 |
| **`severity` 大体单调不减** | 可以有小回落（"雪停了半天"），趋势必须往上 |
| **`severity` 范围 0~1** | D-7 约 0.05~0.2；D-Day = 1.0；D+14 = 1.0 |

**必须写冷的第一次，不要写第三次。** 也就是：**写具体的事，不写感受。**

```
✅ { "day": -7, "severity": 0.1, "hint": "34°C。新闻说是十年最早的连续高温。" }
✅ { "day": 0,  "severity": 1.0, "hint": "41°C。柏油路软了，楼道里没人开窗。" }
✅ { "day": 5,  "severity": 1.0, "hint": "42°C。冰箱停了三天，厨房里全是味道。" }
✅ { "day": 12, "severity": 1.0, "hint": "40°C。楼下有人在分水。你没下去。" }

❌ "热浪无情地炙烤着这座城市。"        ← 拟人 + 抒情
❌ "又是炎热的一天——你还能撑多久？"    ← 破折号 + 空洞
❌ "高温持续，请做好防暑准备。"         ← 公文腔
❌ "记得上次热浪死了很多人。"           ← 环境有记性
```

## 4. 一个完整的"多维度"例子（照这个规格写）

**场次：`blackout_winter`（大停电 · 冬）· 组合家族 · L3**

| 维度 | 取值 | 玩家感受 |
| --- | --- | --- |
| 外界温度 | 沿用寒潮曲线，但 **D+2 起再降 3°C** | 没有取暖，屋里跟着掉 |
| 腐坏速度 | **1.6** | 冰箱停了，冷藏的东西开始坏 |
| 每日消耗 | 燃料 +3（炉子要烧更多）、食物 +1 | 烧得更多，还得吃掉要坏的 |
| 刚需 | 燃料、**食物**（反直觉：平时食物排第二，这里因为"必须吃完"而变刚需） | 什么最值钱变了 |
| 庇护所衰减 | **-2.5/天** | 屋里越来越冷，越冷越要烧 |
| 休息效率 | **0.55** | 睡着也冻醒，体力回不满 |
| 搬运惩罚 | **0.8** | 楼道黑，搬得慢 |
| 行动点 | **-1** | 天黑得早，一天做不了那么多事 |
| 商店供应 | **0.5** | 大半店铺关门（没电、没货） |
| 物价 | **+0.35** | 有货的地方贵得离谱 |
| 事件池权重 | `cold: 3, dark: 2, neighbor: 2` | 碰上的是"冷""黑""邻居" |
| NPC 行为 | **1.3** | **邻居来得更勤**（大家都没电，抱团） |
| 品类效率 | `medicine: 0.8`（药冻住了不好用） | 药品打折 |
| 健康风险 | **1.5/天** | 硬扛真的会掉血 |
| **反直觉** | **"冰箱里的东西必须在两天内吃掉" —— 存货变成了限期任务** | 玩家会先做一件从没做过的事：清冰箱 |
| **独有机制** | `candleLight`（照明变成消耗品，没光就不能整理货架） | L4 才加 |

**这一场的 `decisions`**：

```
1. 前 48 小时该清空冰箱（吃掉要坏的），还是保燃料（夜里更冷）
2. 行动点只剩 2 个 —— 出门找燃料，还是在家把东西理好
3. 邻居来得更勤了，人情能给回款，但每次都要分东西出去
```

**看清楚这个例子在做什么**：它把"停电"这个看起来很单一的事，
变成了**14 个维度同时变化**的一场局 —— 而玩家感受到的只有三句取舍。

## 5. 分批发（**一场一个文件**，因为日历很长）

| 批次 | 内容 | 说明 |
| --- | --- | --- |
| `disaster-00` | **手写标杆 3 场**（热浪 / 洪水 / 大停电） | ★ **先交这一批等确认** —— 它们是后面所有内容的**口径样板** |
| `disaster-temp-01~06` | 温度家族剩 21 场 | 按强度档：轻 / 中 / 重 / 极 |
| `disaster-water-01~04` | 水家族 16 场 | 洪水 / 缺水 / 污染 |
| `disaster-struct-01~04` | 结构家族 16 场 | 地震 / 塌方 / 停电 |
| `disaster-bio-01~04` | 生物家族 16 场 | 疫情 / 虫害 / 霉变 |
| `disaster-social-01~04` | 社会家族 16 场 | 骚乱 / 宵禁 / 断供 |
| `disaster-air-01~03` | 空气家族 12 场 | 沙暴 / 毒雾 / 烟霾 |
| `disaster-combo-01~04` | 组合家族 12~16 场 | 两个内核叠加 |

**每一批 4~6 场**（每个文件 4~6 场是因为日历占了大量篇幅；如果模型输出长度够，
一场一个文件也可以）。

★ **`disaster-00` 那 3 场不要跳** —— 批量生成最怕"没有样板就开始生成"：
第一批会变成事实上的标准，而它多半是错的。

## 6. 关于 L4 的独有机制（**重要，请读**）

`specialMechanics` 里的机制**需要引擎实现**。所以：

- 如果你想出一个好机制（例如"没光就不能整理货架"），
  **请在交付说明里单独列出来，标注"需要引擎支持"** —— 那是给开发者看的建议；
- **不要假设它已经能用**。数据里写了但引擎不认识，玩家看到的就是"这一场和别的没区别"。

可以提的机制方向（给开发者看）：

```
candleLight     照明变成消耗品（没光不能整理）
quarantine      不能出门（行动点归零，只能在家）
maskRequired    出门必须戴口罩（消耗品）
curfew          只能在特定时段出门
ceilingRisk     高处的东西会掉（整理规则反转）
waterRation     水按天配给（不能一次喝完）
```
