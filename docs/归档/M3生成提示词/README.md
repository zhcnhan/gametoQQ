# M3 内容生成提示词（归档）

> **这批文件是"曾经怎么把内容生成出来"的记录，不是现行规范。**
> 2026-10 从桌面 `M3生成/` 移进来，原始位置已删除。

## 这是什么

当时为了让外援 AI 批量产出内容，写了六份提示词交给它：

| 文件 | 生成什么 |
| --- | --- |
| `M3内容生成-0-总纲.md` | 通用口径：批次格式、字段纪律、文案纪律 |
| `M3内容生成-1-物资.md` | 物资（`kind: "item"`） |
| `M3内容生成-2-事件.md` | 白天 / 夜间 / 突发事件 |
| `M3内容生成-3-灾难.md` | 灾难（后来被 [`../../M3-灾难生成工单.md`](../../M3-灾难生成工单.md) 取代） |
| `M3内容生成-4-身份与商店.md` | 身份与点位 |
| `M3内容生成-_内容参照.md` | **从代码导出的 id 清单**（"只能引用这里列出的 id"） |

## 现在还怎么用

**生成方已经不用了** —— 那边的 token 预算耗尽，后续内容由本项目自己写。
留下来的两个用处：

1. **`_内容参照.md` 是"可引用 id 的清单"的样本。** 它的内容是**从代码导出的**，
   所以会过期（当时 17 件物资，现在 57 件）。要新的就重新导一份；
   而字段级的要求可以用 `node scripts/check-content.mjs --explain` 打印 ——
   那个是**活的**（它读的就是校验器自己的规则表），优先用它；
2. **文案纪律那几段仍然有效**，与 [`../../M3-灾难生成工单.md`](../../M3-灾难生成工单.md)
   的 §3 是同一套（不写破折号、不拟人、不煽情、hint ≤30 字）。

## ⚠ 别拿它当规范

这些提示词写在**内容量与接口都还不完整的时候**（那时物资只有 17 件、
灾难的 17 个影响维度一个都没实现）。里面的字段表、区间、
"可用标签"清单都**可能已经过期**。

**现行规范以这两处为准**：

- 字段与区间的唯一真相：`node scripts/check-content.mjs --explain`（读校验器的规则表）；
- 内容合格判据：`npm run check`（含 `check:content` 与 `check:registry` 的换皮判据）。
