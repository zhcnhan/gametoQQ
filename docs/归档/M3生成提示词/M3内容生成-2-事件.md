# 提示词 ②：事件（夜间 / 白天 / 突发）

> 先读 `M3内容生成-0-总纲.md` 与 `M3内容生成-_内容参照.md`。
> **目标量：每类 60~100 条**（现在夜间 6 / 白天 4 / 突发 7）。

---

## 0. 三类事件的**根本区别**（先搞清这个，否则会写串）

| 类型 | 什么时候 | 玩法形状 | 玩家的处境 |
| --- | --- | --- | --- |
| **夜间事件** `nightEvent` | 睡前（生存期每天一次） | **选项题**：选定 → 立刻结算 | 一天结束了，你在屋里，只有你 |
| **白天事件** `dayEvent` | **进店那一下**触发 | **选项题**：但改的是**商店**（价格/库存/限购） | 你在外面，人挤人，有别人在 |
| **突发事件** `emergency` | 生存期随机 | **检查题：没有选项** | 事情发生了，来不及决定 |

### 0.1 ★ 突发事件**不是选项题** —— 这是本项目最重要的一个设计

突发的逻辑是：

> **玩家没法在事情发生的那一刻再决定一次，他早就在整理期决定过了。**

`emergency` 的数据里**没有 options**，只有"要哪个品类、顺手位上要有几件"。
玩家的应对方式是在整理期把急救品放到**门口顺手位** —— 放了就化解，没放就掉血。

**这是"整理 → 战力"这条因果链的落点。** 所以你写突发时，
想的不是"给玩家什么选择"，而是**"暴露他整理时的哪个疏忽"**。

## 1. 夜间事件（`kind: "nightEvent"`）

### 1.1 输出格式

```json
{
  "kind": "nightEvent",
  "batch": "night-01",
  "entries": [
    {
      "id": "n_pipe_knock",
      "text": "水管里有敲击声，隔一会儿一下。",
      "tier": 1,
      "decision": "花体力爬下去关总阀（可能白跑），还是忍着噪音睡觉",
      "options": [
        {
          "label": "下去关阀",
          "outcome": "总阀在楼梯间，拧了三圈。回来时手是湿的。",
          "effect": { "stamina": -4, "mood": 2 }
        },
        {
          "label": "塞上耳朵",
          "outcome": "声音一直在。睡着了。",
          "effect": { "stamina": 4 }
        }
      ]
    }
  ]
}
```

### 1.2 字段规则

| 字段 | 规则 |
| --- | --- |
| `id` | **`n_` 开头** + 小写下划线 |
| `text` | 睡前处境，**1~2 句，≤60 字**。只写看得见/听得见的事 |
| `tier` | 1~4（这一批只出 1~2） |
| `decision` | 必填（总纲 §1.3） |
| `options` | **2~3 条**（不许 1 条、不许 4 条） |
| `options[].label` | **≤8 字**（手机竖屏一行放得下） |
| `options[].outcome` | 选完那一刻看到的一句话。可用 `{spentCash}` 占位符 |
| `options[].effect` | 见下 |

### 1.3 `effect` 可用的字段（**全部**，不要用表里没有的）

| 字段 | 含义 | 典型量 |
| --- | --- | --- |
| `cash` | 现金变化（负=花掉）。**给不起就按有多少给多少** | ±100 以内 |
| `health` / `mood` / `stamina` / `shelter` | 四维变化 | ±2 ~ ±8 |
| `boxDefId` | 顺手带回家一箱货：`box_staple` / `box_medical` / `box_mixed` | — |
| `requireFullCash` | `true` = 必须给得起钱才成立（买货类）。不写 = 有多少给多少（人情类） |

### 1.4 ★ 每个选项都必须是**净收益为正**的（机器校验会拦）

- ✅ 拿到货（`boxDefId`）、现金增加、四维增加（**"睡觉 +4 体力"是标准收获**）
- ❌ 只有代价的选项（`stamina: -4` 并且没有别的）—— **退回**
- ❌ 只改商店/只加限购 —— 那是**处境**，不是奖励

**为什么这么严**：本项目真犯过这个错 —— 有一条选项文案写着"你把架子上的主食拿掉一半"，
而 `effect` 里**根本没有给货**。玩家的原话是
*"我抢了东西买了东西……家里的东西并没有增长啊"*。

### 1.5 配套铁律：**文案承诺什么，`effect` 就必须给什么**

```
文案说"你拿到了两袋米"     → effect 里必须有 boxDefId 或（下一版）grab
文案说"你结了账，花了 40"  → effect 里必须有 cash
文案说"睡得很沉"           → effect 里必须有 stamina 正数
```

**说"拿"就真给，说"买"就真有收支。** 这条不通过就整条退回。

## 2. 白天事件（`kind: "dayEvent"`）

### 2.1 输出格式

```json
{
  "kind": "dayEvent",
  "batch": "day-01",
  "entries": [
    {
      "id": "d_truck_unloading",
      "text": "后门有人在卸货，司机在看手机。纸箱上印着罐头。",
      "onlyShops": ["supermarket"],
      "tier": 1,
      "decision": "趁乱拿两箱（背上重量、且要花时间），还是照常排队买限购的那几件",
      "options": [
        {
          "label": "搬两箱走",
          "outcome": "两箱罐头上了车。司机抬头看了一眼，没说话。",
          "effect": { "grab": { "category": "food", "count": 6 }, "stamina": -6 }
        },
        {
          "label": "照常排队",
          "outcome": "队伍没动。前面的人在数货架。",
          "effect": { "mood": 2 }
        }
      ]
    }
  ]
}
```

### 2.2 与夜间事件的三处不同

1. **`effect` 动的对象不同**：白天改的是**商店与现金**，不是四维为主
2. **可以写 `onlyShops`**：只在这几个点位出现。不写 = 任意点位
3. **`grab` 是白天特有的**：当场拿到货，直接进待拆队列，**重量会照实记进车载**

### 2.3 `effect` 可用字段（白天的全套）

| 字段 | 含义 | 注意 |
| --- | --- | --- |
| `cash` | 现金变化 | ±400 以内 |
| `grab` | `{category, count}` 当场拿货 | 重量会记进 `carLoad`。**它是"我抢到了"** |
| `stockCut` | `{category, count}` 只改商店库存 | ⚠ **不能单独构成一个选项**（玩家不会因为"别人抢走了"得到东西） |
| `limit` | `{category, max}` 只加限购 | ⚠ **不能单独构成一个选项**。限购是**处境**不是奖励 |
| `boxDefId` | 顺带一箱货 | — |
| `stamina` / `mood` | 体力 / 心情 | **只有**这两项四维能在白天动 |
| `priceUp` | 今天全城涨价，`0.15` = 贵 15% | 是处境 |
| `requireFullCash` | 必须给得起钱 | — |

### 2.4 ★ 两条被玩家当场抓出来的纪律（**别重犯**）

1. **限购不能当奖励发。** 有一条选项是"按限购买"，玩家的原话是
   *"限购两件跟我有鸡毛关系，我两件东西也没买到啊"*。
   限购只能当**事件背景**，不能是玩家选出来的结果。
2. **光"通融"（调高限购上限）也不构成一个选项。** 那只是"你能买得更多"，
   还得再花一笔钱才真的有货 —— 所以那种选项**必须同时给 `cash` 或 `grab`**。

### 2.5 `onlyShops` 的用法

黑市商人只在五金店后巷、批发只在农贸市场 —— 这类"位置感"用 `onlyShops` 表达，
**而不是在文案里暗示**。可选值见参照表 §5。

## 3. 突发事件（`kind: "emergency"`）—— **没有选项**

### 3.1 输出格式

```json
{
  "kind": "emergency",
  "batch": "emg-01",
  "entries": [
    {
      "id": "e_frost_night",
      "text": "半夜温度掉到 -31°C。窗户内侧结了一层白霜。",
      "category": "warmth",
      "needOnHandy": 2,
      "lost": 2,
      "consumes": false,
      "tier": 1,
      "decision": "整理期把保暖的东西放到门口顺手位，还是留在货架深处"
    }
  ]
}
```

### 3.2 字段规则

| 字段 | 规则 |
| --- | --- |
| `id` | **`e_` 开头** |
| `text` | 陈述处境的 **1~2 句**。**不写台词腔、不煽情** |
| `category` | **要哪个品类**（7 个之一） |
| `needOnHandy` | 顺手位上要有**几件**才算化解，**1 ~ 6** |
| `lost` | 没化解时按缺货口径受创的**件数**，**1 ~ 4**（1 = 一份缺货的疼） |
| `consumes` | `true` = 化解时真的消耗掉那几件（"炉子熄了"要烧掉一罐燃料） |
| `decision` | 必填 |

### 3.3 ★ 写突发的思路：**它不是选择题，是"暴露疏忽"**

问自己：**"这一条暴露的是玩家整理时的哪个具体选择？"**

| 暴露的疏忽 | 例子 |
| --- | --- |
| 急救品放在了货架最里面 | 有人敲门要创可贴，你翻了很久 |
| 燃料和食物混在一个分区 | 半夜炉子熄了，你摸黑找不到燃料 |
| 水没有放在顺手位 | 楼上漏水，你手边一个桶都没有 |
| 常用的东西被压在大件下面 | 停电了，电池在米袋后面 |

**`consumes: true` 用在哪**：那件事**真的会烧掉东西**的时候（燃料、药、电池）。
不该消耗的东西不要写 `true` —— 玩家会觉得自己被抢了。

### 3.4 突发事件的数量与配比

- 目标 **60~100 条**
- **必须覆盖全部 7 个品类**，而且每个品类至少 6 条 ——
  否则"某个品类永远用不上"会让整理失去意义（参照表 §8 第 1 条红线）
- `needOnHandy` 的分布：1 件（约 30%）、2 件（约 40%）、3 件（约 20%）、4~6 件（约 10%）

## 4. 分批发（每批 20~40 条）

| 批次 | 主题 | 重点 |
| --- | --- | --- |
| `night-01` / `night-02` | 物资与身体 | 交换、损耗、身体状态 |
| `night-03` | 人与记忆 | 关系、旧物、纪念品（奢侈品在这里有用） |
| `day-01` / `day-02` | 商店与人潮 | 物价、限购、插队、抢购、以物易物 |
| `day-03` | 位置与机会 | 用 `onlyShops` 写出"哪家店会发生什么事" |
| `emg-01` ~ `emg-03` | 按品类分批 | 每个品类 6+ 条，覆盖整理疏忽的不同类型 |

## 5. 交之前自查清单

- [ ] 每条都有 `decision`，且**不同条的 `decision` 不是同一个决定**
- [ ] 每个选项**净收益为正**（没有"只有代价"的选项）
- [ ] **文案承诺的，`effect` 真的给了**
- [ ] `label` 全部 ≤8 字
- [ ] `text` 全部 ≤60 字且**没有破折号 / 拟人 / 台词腔 / 环境记性**
- [ ] 引用的 `boxDefId` / `category` / `shopId` 都在参照表里
- [ ] 每条事件**至少有一个选项不是"最划算的那个"**（否则玩家没得选）
- [ ] 交付说明里写了：条数 / **决定分类统计** / 最弱的一条

## 6. 最后：事件是玩家和这个世界的唯一接触面

玩家不会读到灾难设定集。他读到的就是这 60~100 条一两句话。

所以**每一条都在替他回答同一个问题**：
> "东西已经囤了一些，日子还在过 —— 今天会有什么不一样？"

**不要写剧情，写处境。** 玩家要的不是故事，是**下一个决定**。
