# 《囤货末世》开发纪律与踩坑档案

> 这份文件服务两类读者：**接手这个项目的 AI**，以及**将来的人类维护者**。
>
> 它不写玩法（那在 `囤货末世-游戏策划案.md`），只写**工程上怎么做才不会重犯已经犯过的错**。
> 每条教训都附：**怎么发现的 → 为什么之前没发现 → 现在靠什么防住**。
>
> 维护规则：**犯了新错就加一条**；加了防线就写清它拦什么、怎么故意让它失败来验证。
> 不要写"要注意代码质量"这种没用的句子 —— 只写能让下一个人少花一轮的东西。

## 0. 项目里最容易出事的三件事（先读这三条）

### 0.1 缺少"能看见现场"的手段时，不要连续改三轮以上

M2 的拖拽功能上，我因为**看不见真实运行状态**，连续改了 **7 轮**，每一轮都在读代码猜，
每一轮都告诉用户"这次应该好了"，每一轮都被打回。用户最后说：

> "不要再浪费我的钱了，我求你了，我感觉你啥也没修，所有的一切还是之前那样。"

**真正的转折点是放弃猜测、动手补手段**：写了一个能真的把 pointer 事件派发进去的
假 DOM（`src/ui/fakeDom.ts`），以及一个可开关的运行期诊断
（控制台 `__tunhuoTrace = true`）。加上这两样之后，剩下的 5 个根因**一轮一个全部定位**。

**硬规则**：

- 同一个现象**改到第二轮还没解决** → 立刻停止改代码，改为**补手段**：
  要么写能复现它的测试，要么加一条只能靠现场才能看见的诊断输出；
- 加诊断输出**不要**靠"让用户描述现象"。人能描述的只有症状
  （"卡住""不跟手""错位"），而症状到根因之间的距离，正是猜错的地方。
  诊断要输出**分支与原始值**：走了哪条路、坐标是多少、命中了哪个元素；
- 诊断加完**要主动请用户把输出贴回来**，并**一次只问一件事**。

### 0.2 说"修好了"之前，必须有能复现它的东西

M2 期间我多次把"改了"当成"修好了"。代价最大的三次：

| 我说过 | 实际情况 |
| --- | --- |
| "拖拽交换已经独立开了" | 交换走的命令**必然拒绝**，因为起手格已被拿空 |
| "卡住的问题修了（加了看门狗）" | 屏幕层**从未实现 `onCancel`**，看门狗收到却没人收幽灵 |
| "格子加 `max-width` 就好看了" | 那句话本身把 CSS 注释提前闭合，**整条规则失效** |

**硬规则**：报告完成时**必须区分三件事**，而且要写在交付说明里：

1. **已验证**（有测试/有量的数据/用户确认过）；
2. **已实现但未验证**（说清为什么验不了、需要什么条件才能验）；
3. **推测**（明确标注是推测，不要混进前两类）。

### 0.3 改了界面/交互，就必须让用户刷新后复验

M2 里出现过：我改了 `src/ui/ShopScreen.ts`，服务端已经是新版，
但浏览器里是旧模块，于是用户看到"你拿了两袋米"和"这一趟没拿到货"**同时出现** ——
我一度以为是逻辑 bug，查了很久才发现是**页面没刷新**。

**硬规则**：交付任何界面改动时，都要在说明里写一句"**硬刷新（Ctrl+Shift+R）再试**"，
并说清**期望看到什么**（具体到文案/位置），不要只说"你看看"。

## 1. 分层与硬约束（违反会被测试或守卫拦下）

### 1.1 目录职责

```
src/data/     静态数据表（items / boxes / disaster / dayEvents / emergencies / palette…）
src/model/    纯逻辑：类型、货架算法、RNG、数值公式。**不许碰 DOM / window / audio**
src/state/    存档与 store（唯一允许碰 localStorage 的地方是 storage.ts）
src/systems/  玩法命令层。**唯一允许的副作用是 store.commit()**
src/ui/       渲染 + 手势（可以有 DOM）
src/fx/       表现层：图标、音效、弹出动画
src/meta/     deferred.ts（技术欠账登记册）与它的守护测试
scripts/      构建期工具（不参与打包，不进 tsconfig）
```

`systems/` 里**不许出现 `document` / `window` / 任何渲染**。命令层的返回值是
`CommandResult { ok, events }`：

- **`ok` 回答"状态变了吗"**；
- **`events` 回答"变成了什么"**，界面据此播动画/弹提示。

M1 踩过：`fulfillRequest` 在"凑不齐"时**已经改过状态却返回 `ok:false`**，
于是界面弹错误提示，而任何"失败就降级为婉拒"的调用方会错误地扣信任值。
**状态变过就必须 `ok:true`**，用 `events` 表达"变成了什么"。

### 1.2 随机必须走种子化 RNG

- 一律用 `model/rng.ts` 的 `createCursor(run.seed)`，**绝不用 `Math.random`**
  （唯一例外是 `save.ts` 里的设备号 `deviceId`，它不参与玩法）；
- 单局只有 `run.seed` 一个游标并随存档持久化 → "杀进程损失=0" 才成立。

### 1.3 存档

- `SAVE_VERSION` 每次改 schema 都要 +1，并写一条迁移；
- `deserialize` **永不抛异常**：认不出的输入返回 `null`，由界面显示"这一局读不出来"；
- 自愈逻辑集中在 `normalizeRun` / `normalizeMeta`（丢掉未知 id、补齐缺失字段）；
- 改字段后**必须**跑存档往返测试（`serialize` → `deserialize`）。M2 里改
  `SurvivalSnapshot` 的字段时，`save.test.ts` 里的字面量断言**坏过两次** ——
  现在用 `{ ...EMPTY_SURVIVAL_SNAPSHOT }` 这种展开，避免以后每改一个字段就坏一次。

### 1.4 视觉约束（§5A，设计师拍板的，不许自己改）

- 纸底 `#f7f3ea` / 墨色 `#2c2c2a` / **朱红 `#c8372d` 是唯一点缀色，只用于警告与重要交互**；
- **暖黄 `#f2c94c` 只用于"安全 / 室内"语义**，别处不许用；
- `scripts/check-style.mjs` 会检查色相没被改动。

### 1.5 可读性与触点

- 格子触点最小 56px（提示词 0 第 7 条，也是 `.slot` 的 `min-height`）；
- **任何动作都要可中断**（§4A）：随时被叫走、回来还能接着做；
- **不许有"点了没反应"的按钮**（行动点用完就 `disabled` 并给 `title`）。

## 2. 已犯过的错（按代价排序，每条都有防线）

### 2.1 ★★★ 拖拽交换：把"中间状态"当成了"终态"

**现象**：把 A 拖到 B 上，弹出"两个格子都得有东西才谈得上互换"。
用户原话：*"这不是傻比吗"*。

**根因**：拖拽的物理过程是 `onDragStart` **先把起手格的东西拿进手里**
（`pickupFromShelf`），所以**起手那一格是空的**。而我让它去调 `swapSlots`，
那个命令要求 `from` 与 `to` **两格都有东西** → **必然拒绝**。
那句提示其实一直在说真话：起手格确实空着。

**为什么之前没发现**：命令层的单元测试是**绿的** —— `swapSlots` 本身没问题，
错的是"在拖拽这个中间状态下不该调它"。这个错误**只在屏幕级才显形**。

**修法**：新增 `swapHeldWithSlot(store, session, from, to)`，把模型改成拖拽真实的中间状态：

```
from 格（空） ← target 那件
to   格       ← held（手里那件）
手里          ← 空
```

`swapSlots`（要求两格都非空）保留，注释里写明两者分工 —— **混用就会重现这条 bug**。

**防线**：`src/ui/swapDrop.test.ts`（屏幕级，跑真实手势 + 真实命令层）。

**给后来者的规则**：**写命令时先问"调用它的那一刻，盘面真的是我以为的样子吗"**。
凡是"拖拽 / 多步操作"这类有中间状态的交互，中间状态必须写进命令的前置条件里，
或者为中间状态单独开一个命令。

### 2.2 ★★★ 手势被取消时没人收尾（`onCancel` 从未实现）

**现象**：拖动"卡住"，屏幕上留一个不动的小方块，得点一下原格子才好。

**根因**：`drag.ts` 有一条 `onCancel` 通路（长按成立前判定为滚动、看门狗判定手势僵死），
而 `OrganizeScreen` **从来没有实现它**。看门狗虽然把手势结束了，**幽灵却没人摘**。

**防线**：`drag.test.ts` 里断言 `onCancel` 会被调用；屏幕层的 `cancelDrag()` 收幽灵。

**给后来者的规则**：**钩子函数定义了就必须有人实现**。加一条回调通路时，
同时在调用方搜索"这个回调我接了吗" —— 尤其是错误/中断路径，
它们平时不跑，所以不会被随手发现。

### 2.3 ★★★ 手势监听器残留（每次重绘都在打断拖拽）

**现象**：手机上"完全不跟手"，幽灵一顿一顿。

**根因（两层）**：

1. `renderRoom` 用 `innerHTML` 换掉整间房，而 `attachPointerGesture` 在拖拽期间会往
   **window** 上加监听 —— 手势没跑完就重绘（**拾取一件就会重绘**），
   那些 window 监听器就**永远留着**，继续响应之后每一次 `pointerup`，
   对着已经不在屏幕上的旧元素回调。**量到的数字：一次拖拽后 window 上挂着 4 个 `pointerup`**；
2. `drag.ts` 的 detacher 在摘监听时**顺手取消了进行中的手势**
   （`if (active && active.el === el) cancelActive()`），于是**每一帧渲染都打断拖拽**，
   而且它是递归的（`cancelDrag()` 结尾又 `render()`）。

**诊断日志一眼看出的样子**：

```
clearGestureBindings: 摘掉 72 个手势（其中若有正在拖的那个，会被打断）
cancelDrag（手势被打断）          ← 每一帧都来一次
```

**修法**：

- **window 监听器改成"常驻 + 一个活跃手势"**：只在模块加载时装一次，
  **没有 add/remove 配对，就没有配错的机会**；元素被换掉也不影响收尾
  （收尾只依赖 `active` 变量）；
- detacher **只摘元素自己的 `pointerdown`**，不再碰进行中的手势。

> **核心原则："元素没了"不等于"手势该结束"。手势的生死由指针决定，不由 DOM 决定。**

**防线**：`drag.test.ts` 有两条专门守它 ——
「摘掉元素监听**不许**打断进行中的手势」与「window 上的监听器常驻且不累积」。

### 2.4 ★★ 格子上缺少 `touch-action: none`

**现象**：手机上一次拖拽"每约 6px 就断一次"（诊断日志直接量出来的）。

**根因**：浏览器默认认为格子那块区域**可以滚动页面**，于是手指按住移动几像素后
**接管**手势去滚动，同时发 `pointercancel` —— 我们收到就按"被打断"收尾。

**修法**：`.slot` 与 `.box` 补 `touch-action: none`。滚动仍可从货架卡留白、
卡片之间的缝、页面其它区域发起。

**防线**：`scripts/check-style.mjs` 第 ⑤ 条 —— 这两个类必须有 `touch-action: none`。
**这条极易被当成"多余样式"删掉，而删掉之后没有任何报错。**

### 2.5 ★★ 覆盖层挡住落点（`pointer-events` **不是**继承属性）

**现象**：*"把 A 正正好好放在 B 上反而判定不到，中心周围一小圈才能判定到。"*

**根因**：幽灵跟着指针、**正好在指针底下**，而 `elementFromPoint` 命中的是**最上层**元素。
幽灵挂在 `pointer-events: none` 的 `.fx-layer` 里，但**一条针对 `.drag-ghost` 自身的规则
会覆盖继承** —— 而 `pointer-events` 的初始值就是 `auto`，所以幽灵变成了可命中元素。

**关键知识点**：`pointer-events` **不是继承属性**。父层写 `none` 管不到子元素，
**子元素必须自己写**。

**修法（两手，都要）**：

1. `.drag-ghost` 自己补 `pointer-events: none`；
2. **落点判定加"几何兜底"**：命中的元素属于 `[data-fx]`（特效层）时，
   **不看它，改按坐标自己找那一格**（`slotUnderPoint`）。这样"幽灵在哪儿、
   它吃不吃指针事件、浏览器怎么排序"都不再影响判定。

**给后来者的规则**：**证据比机制更重要**。我赌"幽灵没有 `pointer-events`"赌错一次
（改了之后用户说没变化），就不该赌第二次 —— 直接**从结构上绕开**。
凡是"谁在指针最上层"这类浏览器说法，能绕开就绕开：位置是我们自己设的，可信。

**防线**：`scripts/check-style.mjs` 第 ⑥ 条（`.drag-ghost` 必须有 `pointer-events: none`）
+ `fakeDom.test.ts` 的命中测试尊重 `pointerEvents`。

### 2.6 ★★ 拖拽幽灵创建时没设坐标

**现象**：*"拖动的影子直接在 nmb 最左上角了"*。

**根因**：幽灵是 `position: fixed`，靠 inline 的 `left`/`top` 定位；
`beginDrag` 创建它时**一个坐标都没设**，要等第一次 `onDragMove` 才跳到指针处。
鼠标路径下这个空档极小（移动 6px 就进拖拽，紧接着就有 move），
但**触摸长按路径是"先出现、后跳"**：长按 220ms 成立时手指已经停着不动，
而 `onDragMove` 要等手指**再动一下**才来 —— 这中间幽灵钉在 `(0,0)`。

**修法**：把起手坐标**当参数传进 `beginDrag`**（`onDragStart` 的回调本来就给了 point），
创建时就用它摆好位置；抽出 `moveGhostTo()` 让"初始摆位"与"跟随移动"走同一段代码。

**给后来者的规则**：**"某处一定会很快调用另一个方法"是一种假设，要验证**。
凡是"创建即显示"的元素，创建时就把可见状态设完整。

### 2.7 ★★ 落点用了上一帧的缓存

**现象**：拖到 B 上，却按"起手那一格"判定。

**根因**：`endDrag` 原来优先用 `this.hoverEl`（**上一帧悬停到的那一格**），
而它与"松手这一刻指针在哪"**不保证一致**：最后一帧移动太小没触发 `moveDrag`、
中途元素被重绘换掉过、快速松手时最后一次 move 与 up 之间还差一点。

**修法**：**按松手坐标重新判定**（`pickDropSlot(point)`），旧缓存只作兜底。

**给后来者的规则**：**要判定"现在"，就用现在的输入重算**，不要相信任何"上一帧"的缓存。
缓存只适合"用来省算力"，不适合"用来做判断"。

### 2.8 ★★ 用"会话级标记"描述本可以算出来的事

**背景**：为了区分"手里这件是刚拿起来的"与"上一步没放下的一半"，
我加了一个 `DragState.partial` + `holdingPartial` 标记。

**后果**：它与"这一趟从哪格拖起"（`dragOrigin`）是**同一件事的两种说法**，
而两套说法会打架 —— 直接导致"拖两件互换却被拒绝"那条 bug。

**修法**：删掉 `partial` 那一对标记，**只留 `dragOrigin` 一个来源**，
并让 `pickDropSlot` 与 `nearestLegalSlot` 共用同一套判据。

**给后来者的规则**：**同一件事只留一个真相来源**。要描述状态时先问
"这个能从现有数据算出来吗" —— 能算就别存。

### 2.9 ★★★ CSS 注释不能嵌套（而且坏得极其隐蔽）

**现象**：开发服务器抛 `[postcss] Unknown word 237px`，**整条 `.shelf-grid` 规则作废**。

**根因**：我在注释里写了一行**包含注释符的代码示例**：

```css
 *     grid-template-columns: repeat(6, minmax(0, 1fr));   /* 桌面上每列 313px */
```

那个内层 `*/` **提前把注释收掉了**，后面的 `237px` 就变成解析器眼里的未知词。

**更坏的一次**：我移动代码块时切片起点算错一行，留下一个**孤立的 `/*`** ——
它没有报错，因为后面不远处有个 `*/` 把它闭合了，只**静默吞掉一行**。

**规则**：

- 注释里**绝不写一对注释符**（哪怕为了举例子）。举例请用 `→`，或把斜杠写成全角；
- 移动大段 CSS 之后，**必须**扫一遍嵌套注释与未闭合注释：
  正文里 `/*` 与 `*/` 必须配平，且不出现内层 `/*`。

### 2.10 ★★ 「响应式」改动的溢出账要算，不要只看一个视口

M2 里我把 6 列网格从 `repeat(6, minmax(0, 1fr))` 改成轨道封顶 76px，
结果**忘了算窄屏**：6 × 56px + 5 × 3px = **351px**，比 320px 视口的可用宽度（约 306px）宽。

**规则**：任何"给尺寸加上限"的改动，都要**同时算三档**：
**320px（iPhone SE 这类最窄）/ 375~390px（主目标）/ 桌面**。
三档都要写出"可用宽度 → 轨道宽 → 总宽"，并确认不溢出（见 §3.8 的算法脚本）。

### 2.11 ★★ 界面问题先量"层次"，不要先怀疑配色

**现象**：用户说*"整个程序的界面色调太奇怪了，看久了有点疲劳，一点都不高级"*。

**我的错**：差点直接去调色相 —— 而调色板是策划案 §5A 拍板的，不该自己动。

**量化之后才看清**：把全站边框数了一遍，**13 类元素用 2px 以上的纯墨粗边框**，
剩下 8 类也不过 1.5px。**整个界面只有"响"和"比较响"两档，没有安静的那一档** ——
满屏都在喊。再加上"每张卡片右下都有 3~4px 实心墨影"，同一种重量铺满整块屏幕。

**修法**：分三档（2.5px 锚点 / 1.5px 内容行 / 1px 控件）+ 影子只给真正浮起来的东西，
**色相一个都没动**。

**规则**：用户说"不好看"时，先**数**（边框宽度分布、颜色数量、字号档数），
再决定改什么。**"不好看"通常是"缺层次"，不是"颜色不对"。**

### 2.12 ★ 给元素加 `max-width` 却没给容器/轨道加

**现象**：桌面上"格子是乱的"。

**根因**：给格子加了 `max-width: 76px`，却**没给网格轨道加**：

```css
grid-template-columns: repeat(6, minmax(0, 1fr));   /* 1916px 下每列 313px */
.slot { max-width: 76px }                            /* 格子只占 76px */
```

于是**每列有 237px 是空的**，而且那片空档是**落点判定的死区**（`elementFromPoint` 命中不到）。

**修法**：上限加在**轨道**上（`minmax(56px, 76px)`），并让格子 `width: 100%` **填满轨道**。

**规则**：**给子元素设上限时，问一句"它的容器/轨道有上限吗"**。

## 3. 工具链的坑（都是实际踩过的）

### 3.1 vitest 读不到 CSS 原文

`import.meta.glob('…/*.css', { query: '?raw' })` 会**匹配到键、内容却是空串**。
试过三种写法（`?raw` / `as: 'raw'` / `../**/*.css`），**全是 0 长度**。
vitest 对 `.css` 有专门的资产处理，抢在 `?raw` 之前。

**结论**：

- 需要检查样式表 → **用构建期脚本**（`node scripts/check-style.mjs`），不要写单测；
- **`.txt` 的 `?raw` 是正常的**（存档夹具就是这么读的），别把这条结论套到所有文件上。

### 3.2 假 DOM 的坑（`src/ui/fakeDom.ts`）

这个假体是 M2 最有价值的产出之一（它抓出了 §2.2、§2.3、§2.1 三条真 bug），
但它自己踩过一串坑，**后来者改它之前请先读这几条**：

| 坑 | 表现 | 修法 |
| --- | --- | --- |
| 扁平元素索引会过期 | `innerHTML` 重建后命中测试永远返回 `null`，所有断言在验空气 | **从文档树遍历**，不要查手工索引 |
| `createElement` 没设 `ownerDocument` | 根元素的 `innerHTML` 从不被解析 | 在 `createElement` 里就设上 |
| 组合选择器被当成后代选择器 | `[data-slot][data-shelf="x"]` 一个都匹配不到 | 紧挨着的多个条件按"与"处理 |
| `class` 没同步到 `classList` | `querySelector('.slot')` 返回空 | 解析属性时同步 `className` |
| 自定义解析器把兄弟节点吃光 | 第一个 `<button>` 吞到**最后一个** `</button>` | 按同名标签开合配对计数 |
| 定时器不推进系统时钟 | 按真实时钟判断的逻辑（看门狗）永远测不到 | `tick()` **先推进 `Date.now()` 再跑定时器** |
| `pointer-events` 语义写错 | 以为子元素继承祖先的 `none` | **不是继承属性**，只看元素自己的值 |
| 病理输入导致内存爆炸 | worker 吃到 4GB、跑 40 秒后崩 | 解析加**硬上限**（2000 元素 / 60 层），超限**明确报错** |

**一条重要边界**：假体在**层叠顺序**上不可靠（它用"深度优先 + 后者胜"近似）。
所以**不要**用它测"谁盖住谁"这类问题 —— 那种测试要真浏览器。
M2 里我为此写过一条测试，结果它成了内存爆炸的来源，最后删掉并写明原因。

### 3.3 `drag.ts` 是模块级单例，测试要显式复位

`active` / `watchdog` / `installedOn` 都是**模块级**变量，而单测里每个用例都会
`installFakeWindow()` 造一个新 window → **状态跨用例残留**，
"这个 window 上挂了几份监听"这类断言数字虚高、行为互相干扰。

**修法**：导出 `__resetGesturesForTest()`，每个用例开新 window 前调用。
（`installedOn` 存的是 window **对象**而不是布尔值，所以换了 window 会自动重新安装监听。）

### 3.4 编辑文件时的工具坑

- **PowerShell 的多行字符串与反引号转义极不可靠**。我在它上面浪费了大量轮次：
  中文被转成乱码、多行字符串被吞、`[` 被解析成数组下标、模板字符串里的反引号冲突。
  **结论：改代码用专门的编辑工具，不要用 shell 拼字符串**；
- **不要用 shell 批量替换源码**。需要批量清理时，写一个**一次性脚本文件**
  （见 `scripts/strip-trace.mjs`），既可靠又留下记录；
- **写入时用无 BOM 的 UTF-8**；写前确认文件原本有没有 BOM；
- 若怀疑编码坏了，**先看原始字节**（UTF-8 三字节 vs 双重编码），
  不要凭控制台显示判断 —— 控制台本身会骗人（`Invoke-WebRequest` 的转码就骗过我一次）。

### 3.5 git 的坑

- **`git checkout <file>` 会连未提交的改动一起丢**。我差点因此丢掉一次核心修复，
  是样式守卫当场报错才发现的。要"临时改坏再验证"，先复制到临时目录，或 `git stash`；
- **验证一个守卫真的有效，必须故意让它失败一次**，看完退出码再恢复 ——
  没被验证过的守卫常常只是"看起来在守"。

### 3.6 构建与门禁

```
npm run typecheck     tsc --noEmit
npm run check:style   node scripts/check-style.mjs
npm run test          vitest run
npm run check         上面三个串起来
npm run build         npm run check && tsc --noEmit && vite build
npm run make-save     vite-node scripts/make-save.mjs（造测试存档）
```

**规则：不允许绕过门禁提交。** 某一轮我为了推进而跳过 `check`
（因为有 1 条测试红着），结果那个红测试正好是另一个 bug 的信号。

### 3.7 门禁脚本必须"解层叠"，否则它报假账

`check-style.mjs` 的第一版是"只要有一条规则写了粗边框就算它响"。
但 CSS 是**层叠**的：后面那条 `border: 1.5px` 才是生效值。
于是它把**已经被降级的元素**也报成响的（13 类里有 9 类是假账）。

> **一个满嘴假账的守卫比没有守卫更糟：人会学会忽略它。**

修法：按源码顺序解出每个类**最终生效**的 `border` / `box-shadow`。
同理，**覆盖块必须在样式表最末尾**（同权重靠"后来者赢"），
而且**覆盖要用简写 `border` 而不是 `border-width`** ——
后者会保留原来的颜色，那是"看着改了、其实没改"（这个错我也犯过）。

### 3.8 响应式自检（贴进 node 就能用）

```js
// 轨道宽度 = clamp(56, 可用宽度/列数, 76)；可用宽度 ≈ 视口 − 24(页面留白) − 12(卡片留白)
for (const v of [320, 375, 390, 430, 768, 1200, 1916]) {
  const cols = 6, gap = 3;
  const avail = v - 36;
  const raw = (avail - gap * (cols - 1)) / cols;
  const t = v <= 400 ? Math.max(0, raw) : Math.max(56, Math.min(76, raw));
  const total = t * cols + gap * (cols - 1);
  console.log(v, '轨道', t.toFixed(1), '总宽', total.toFixed(1), total > avail + 0.5 ? '★溢出' : '');
}
```

期望（M2 收尾时的实测值）：320→44.8、375→54.0、390→56.5、768/1200/1916→76（封顶），
桌面总宽恒为 471px 且居中。

## 4. 测试怎么写（M2 之后的约定）

### 4.1 层次

| 层 | 位置 | 测什么 |
| --- | --- | --- |
| 纯逻辑 | `src/model/*.test.ts` | 货架算法、归位率、FEFO、RNG |
| 命令层 | `src/systems/*.test.ts` | 命令的前置条件、事件、边界、守恒 |
| 表现层行为 | `src/ui/*.test.ts` | 手势状态机（`drag.test.ts`）、屏幕级路径（`swapDrop.test.ts`） |
| 假体自检 | `src/ui/fakeDom.test.ts` | 假体本身对不对（**改了假体必须跑**） |
| 存档夹具 | `src/tools/saveFixtures.test.ts` | 夹具能被 `migrate` 读回来、结构符合断言 |
| 样式 | `scripts/check-style.mjs` | 视觉层次、`touch-action`、`pointer-events`、色相 |

### 4.2 每个"玩法数值改动"必须先跑探针

策划案 §12 的纪律：数值改动要跑永久测试，三档对照：

- **好档活**（全上架 + 写全清单 + FEFO + 顺手位）→ 活满 14 天；
- **乱档倒**（全堆纸箱）→ 约 D+10 倒下；
- **中途补救有用**（D+2 补救能活，D+5 补救仍然倒）。

**先量再改**，把数字写进策划案 §12 的"实测验证表"。

### 4.3 测试文件里不要留诊断脚手架

M2 里我留过一个整块 `describe.skip` 的屏幕级脚手架和一个跑不通的看门狗用例。
它们**有价值**（前者抓出过 3 个真 bug），但**挂在那里会让人以为测试是绿的**。

**规则**：跑不通的测试要么修好、要么删掉并在**原处写明原因与将来怎么做**。
不许留无言的红/跳过项。

## 5. 文档纪律

### 5.1 三份文件的分工

| 文件 | 回答什么 | 谁需要 |
| --- | --- | --- |
| `docs/囤货末世-游戏策划案.md` | **玩法决策**：为什么这样设计、数值怎么算、路线图、候补清单、已拍板决策 | 设计师、接手开发 |
| `docs/囤货末世-开发纪律.md`（本文件） | **工程怎么做**：踩过的坑、防线、工具链、测试约定 | 接手的 AI、维护者 |
| `src/meta/deferred.ts` | **技术欠账登记册**：已知没做完的事，带 `DEFERRED(D-xx)` 代码标记 | 开发者 |

### 5.2 什么时候写哪里

- **新的玩法决策** → 策划案 §12，写清"问题实测 → 账怎么算 → 改动 → 实测验证表"；
- **新的技术欠账** → `deferred.ts` 加一条（从 D-16 往后编号），
  并在代码里留 `DEFERRED(D-xx)` 标记；
  **`deferred.test.ts` 会做双向校验**：代码里的标记必须在册、在册的必须能在代码里找到；
- **里程碑变化** → 策划案 §10；**M3 候补** → §10A；
- **新的工程教训** → 本文件 §2 或 §3，**附"怎么发现的"与"靠什么防住"**。

### 5.3 代码注释要写"为什么"

M2 里最有价值的注释长这样（写清"为什么必须这样、不这样会怎样"）：

> `pointer-events` **不是继承属性**。幽灵挂在 `.fx-layer` 里并不能让它免于命中 ——
> 它必须自己写这一条。

**规则**：注释解释**约束与后果**，不要复述代码在做什么。
凡是"看起来可以简化、但简化后会坏"的地方，都要写明"别删，因为…"。

## 6. 交付与沟通

### 6.1 报告要说清"验证状态"

见 §0.2。交付说明里必须能区分**已验证 / 已实现未验证 / 推测**。
如果你改的是界面或交互，**必须**给出"刷新后应该看到什么"。

### 6.2 不要替用户做手感决策

M2 的用户是设计权威。这类问题**列选项 + 给代价**，不要自己定：

- 吸附的宽容度（只认格子 / 吸附最近 / 精确优先+吸附兜底）—— 用户选了第三种；
- 桌面留白怎么处理；
- 界面"不好看"要往哪个方向调。

而**机制问题**（bug、可达性、溢出、无死按钮）该自己定，直接修。

### 6.3 数字比形容词有用

- ❌"界面太花" → ✅"13 类元素用 2px 以上粗边框，只有两档，没有安静的一档"；
- ❌"拖拽卡住" → ✅"每约 6px 一次 `cancelDrag`；一次拖拽后 window 上挂 4 个 `pointerup`"；
- ❌"箱子太多会不会卡" → ✅"100 箱 / 1104 件 / 44KB 存档"。
