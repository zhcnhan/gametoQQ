## 1. M5 的目标

M4 的目标是「**把每一个方面都打磨到与「物品整理」这件核心玩法相关**」——
那件事做完了。M5 的目标是另外一件，而且它同样只有一个：

> **让这一局"看起来"就是你正在经历的那一场灾难。**

这句话具体指两件事，两件都要做到才算数：

1. **视觉基调承载威胁**（现在不承载）—— 玩家在 116 场灾难里看到的是同一张米黄纸。
   用户在 D-33 里的原话是"太奶油风了，一点都不灾难"，这句是准的；
2. **先知的身份看得见**（现在看不见）—— 日历只在开局出现一次，进了囤货期就再也
   找不到了；而"我知道要发生什么"正是这个游戏的第一个爽点（§5 爽点①）。

★ 与 M4 的关系：M4 让**机制**与整理有关，M5 让**屏幕**与这一场有关。
两条轴不重叠，所以 M5 不是 M4 的续集，是另一条轴的第一轮。

## 2. 两件已拍板（2026-10，细节在策划案 §12A「决策 E」）

★ 纪律 §6.2：**手感与视觉偏好不替用户决定**。下面两件都已由用户选定，
决策与实测过程记在 **`docs/囤货末世-游戏策划案.md` §12A 的
「[拍板 v0.13 · 决策 E]」**（那一节是 D-33 要求"动手前先立的决策"）。
这里只留结论与它带来的新约束。

### 已定 ①：视觉基调 = 「灾难本身决定配色」

★ 但**不是**"页面底刷成这一场的灾难色"—— 那一版**量出来是功能失效**：

| 量什么 | 实测 |
| --- | --- |
| 墨 `#2c2c2a` 压在 116 场的**代表色**上 | 中位 **2.3 : 1**（最好的暴雪 4.56 : 1）；低于 4.5:1 的场次 **113 / 116** |
| 朱红 `#c8372d` 压在代表色上 | 最差 **1.01 : 1**；低于 3:1 的 **116 / 116** —— **警告色等于没有** |
| 暖黄 `#f2c94c` 压在代表色上 | 中位 2.0 : 1 —— **"安全"信号也消失** |

所以"灾难决定配色"落成的规则是：

> **底色由 `family` 决定（7 类），窗户由 `windowScene` 决定（116 个 key）。**

| 层 | 谁说了算 | 怎么变 |
| --- | --- | --- |
| 页面底（纸 / 卡片 / 沉底） | `DisasterProfile.family` | L* 定死在 **90**（现在 95.9），色相与饱和按家族 |
| 窗外那一条带子 | `windowScene` | **不动**（M4 那 116 组渐变不跟着重调） |
| 纹理 / 飘落 | `windowScene` 的 `fall` | 雪 / 灰 / 雨 / 尘 —— 同家族靠它分开 |
| 警告 / 安全 | 不参与 | 朱红与暖黄保持原值（§5A 红线） |

★★ **"逐场一个页面底色"被实测否决，别再回头试**：116 场里同家族有 15~25 场，
往白里提出 116 个底之后按「色相 6° / 饱和 4% / 明度 2 个 L*」量化，
**18 组撞车、涉及 100 场，完全同色的 60 场**。硬凑只有两条路
（拉饱和度 → 就是上面"正文不可读"那条；手写 116 个色值 → 每次加灾难都要重验撞色），
而它们换来的区分度**低于**窗外那一条带子本来就有的。

**新约束（改进 D-33 那一步时的判据）**：墨 **≥ 11**、ink-70 **≥ 4.5**、朱红 **≥ 4.15**
（★ 这三个下限是照"现有一套的最小值再留一点余量"定的：11.31 / 4.75 / 4.20）、
三档底 L* 跨度从现在的 6.5 拉到 **≥ 14**、家族色相与朱红（OKLCH H≈29.5）距离 ≥ 25°
（结构取 58 就是为了这条）。
⚠ **算 ink-70 / ink-40 时必须先按 alpha 合到底上**（它们是 `rgba`）—— 决策 E 的初版把它们
当成不透明的 `#6f6f6b` / `#a8a8a5`，全表低了约 0.5（纸底写 4.56、真值 5.04）。
`src/data/familyTone.test.ts` 现在把两个口径都钉住了。

### 已定 ②：先知日历 = 顶栏给「倒计时 + 强度条 + 这一场要什么」，「哪几天最难」放进展开层

保住 §6.1「日历是**规划乐趣**的来源」——"先知要我主动去问"比"先知把答案贴在脸上"更像先知。

★ 这一层**不缺数据**：实测每场内部 `severity` 落差中位 **0.9**（范围 0.9~1.0，
落差为 0 的场次 **0**），所以"哪几天最难"只是展示位置的问题。
⚠ 但**不要把 severity 接到页面底色上**：底色逐日变化幅度必须很小
（L* 前后只许动 2 个点），否则低严重度那天看起来像**另一场灾难**。

#### ★★ D-34 的遗留：结算页的"比上一局"刷新即消失

`settleRunMeta` 有幂等闸（`run.metaSettled`），第二遍返回 `null`，
于是"上一局是什么"这个**结算那一刻才有**的信息在刷新之后就没了

### 第二组：机制级的两件（各要一个设计答案）

#### ⛔ 前置：W-10「一袋米占四格」—— 物资的物理大小

M4 的结论是"**不在本轮实现**"，理由是缺的不是接线，是设计答案

它值得做，因为它直接加厚 §10.1A 第 1 条：
"一袋米占掉四格，值不值"是一个**现在不存在**的取舍，
而它恰好是本作的核心动作。**三个选项，请用户选一个**：

| 方案 | 口径 | 代价 |
| --- | --- | --- |
| **A. 只给"大类"定尺寸**（建议） | 只给米 / 水 / 燃料这类**整件**定 2 或 4 格，其余全 1 格（约 20 件要标，101 件不动） | 小：放置 / 合并 / 拖动 / 容量 / 存档五处都要动，但平衡面只有 20 件 |
| **B. 全表 121 件逐件定** | 每件都有尺寸 | 大：121 件全部回到平衡桌上，而且**价格要不要跟着改**会变成第二个问题 |
| **C. 不做** | 保留"一格一栈" | 零。核心动作少了一层厚度 |

⚠ **三条共同的前置**：它一次动**放置 / 合并 / 拖动 / 容量 / 存档**五处，
而且会推翻"一格一栈"这个前提 —— 全仓有几处代码**默认了它**
（`model/shelf.ts` 的 `getStack` / `setSlotStack`、拖动落点判定、`countInPlace`）。
选 A 或 B 之前要先做一次**接线审查**（纪律 §4A.5），把"哪些地方假设了一格一栈"数清楚。

  "最平的一场"跨度只有 **10.2**，而中位是 34.9 —— 只看中位数会以为没问题；
- **视觉与先知拆成两次提交** —— D-33 自己写着"不要混成一句把界面改好看"，
  而它们一个动配色、一个动信息组织，混在一起之后"哪一半让玩家觉得不同"就测不出来；
- **三条"⛔ 前置"都排在前面** —— W-10 / D-28 / D-35 缺的都是**设计答案**，
  而它们各自的答案决定后面要不要动 `SAVE_VERSION`、要不要动平衡表。
  先要答案，再要工期。

## 5. 验收口径

M5 做完时，下面每一条都要能被**量出来**（不是"感觉好多了"）：

- [ ] **视觉基调承载威胁**：三档底（卡片 / 纸 / 沉底）的 L* 跨度从现在的 **6.5**
      拉到 **≥ 14**，且这条判据写成一个可复跑的探针（形如 M4 的 `scripts/_probe-contrast.ts`）；
- [ ] **家族真的换了底色**：7 个家族各一个底，且**同家族的两场底色相同**（这是刻意的，
      防止有人回头去凑"逐场一个底"—— 那条路已被实测否决，见 §2）；家族色相与朱红距离 **≥ 25°**；
- [ ] **全部文字色在 7 个底上都过关**：墨 **≥ 11**、ink-70 **≥ 4.5**、朱红 **≥ 4.15**
      （新加一条守卫，按家族逐个断言 —— `check-style.mjs` 第 ⑧ 条只数"类数 ≤ 9"，
      **不验对比度**，暗底可以把九个看起来一样的边框全部留下来；
      ⚠ 算 ink-70 / ink-40 要**先按 alpha 合到底上**，它们是 `rgba`）；
- [ ] **116 组窗外配色没有被顺手改掉**：M4 那条守卫继续绿，
      且新加一条钉住"116 个 key 仍然各不相同、回退 0 场"
      （它们从"窗外一条带子"升级成"全屏唯一的逐场颜色"，改坏它等于把这一场的身份证弄丢）；
- [ ] **先知日历在生存期的每一屏都抬头可见**，且它说的是**这一场**的信息
      （不是"寒潮"这种写死的名字）—— 用一条屏幕级测试钉住：换一场灾难，顶栏那一行跟着变；
      点开之后的展开层里有逐日"哪几天最难"（`hint`），而**顶栏不直接给**；
- [ ] **320 / 375 / 390 三档零溢出**（顶栏塞进日历之后重新验）；
- [ ] **每条"⛔ 前置"要么有了设计答案、要么明确不做** ——
      不许出现第四条"登记着但没人知道该怎么办"的账。

★ 与 M4 的同一条纪律：**验收要落在断言上，不要落在手感描述上**（纪律 §6.3）。
"看起来更灾难了"必须能被翻译成一个数，否则它就不是验收项。

## 6. M5 明确**不做**的（留档，免得下次审查重新讨论一遍）

- **不重做交互手感**：M0~M2 那一轮（拖拽六条根因 + `touch-action` 三次结论）已经到位，
  M5 动的是**看**，不是**摸**；
- **不加新灾难 / 新物资 / 新事件来"撑"视觉**：视觉重构的成败与内容量无关，
  116 场已经足够验"这一场看起来是不是这一场"；
- **不给"电"和"物资尺寸"顺手造一套机制**：它们各自要先有一个设计答案（见第二组），
  顺手做出来的版本一定会在下一次审查里被记成"承诺了但没接线"（纪律 §2.19 那 6 处的形状）。
