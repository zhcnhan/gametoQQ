### ① 底色跟着灾难**家族**走（`src/data/familyTone.ts`）

> **底色由 `family` 决定（7 类），窗户由 `windowScene` 决定（116 个 key）。**

| 层 | 谁说了算 | 怎么变 |
| --- | --- | --- |
| 页面底（纸 / 卡片 / 沉底） | `DisasterProfile.family` | L* 定死，色相与饱和按家族 |
| 窗外那一条带子 | `windowScene` | **不重调** —— 它升级成"全屏唯一的逐场颜色" |
| 纹理 / 飘落 | `windowScene` 的 `fall` | 雪 / 灰 / 雨 / 尘 —— 同家族靠它分开 |
| 警告 / 安全 | 不参与 | 朱红与暖黄保持原值（§5A 红线） |

- `:root` **没动**：家族色调由 `src/ui/Router.ts` 的 `applyTone()` 写进 `<body>` 的
  **内联变量**（`--paper` / `--card` / `--paper-2`）。理由是 `src/style.css` 里有
  343 处 `var(--paper…)`，挂家族类名要在 CSS 里再抄一份 7 家族的映射表 ——
  那份表没有第二个读者却会被抄错。
- ★★ **"逐场一个页面底色"被实测否决，别再回头试**：116 场里同家族有 15~25 场，
  硬凑只有"拉饱和度"（正文当场读不了）或"手写 116 个色值"（每次加灾难都要重验撞色），
  换来的区分度**低于**窗外那条带子本来就有的。所以**同家族两场的底色完全相同是刻意的**。
- 定稿实测：墨最差 **11.31** / ink-70 **4.75** / 朱红 **4.20**；三档跨度 **6.5 → 13.8**；
  116 场落到 **7 个底**；七个家族色相离朱红全部 ≥ 25°。
- ⚠ **量它必须先合底**：`--ink-70` / `--ink-40` 是半透明的墨，要先按 alpha 合到那个
  家族的纸底上再算。决策 E 初版把它们当成不透明色，全表虚低约 0.5。
  `src/data/familyTone.test.ts` 把两个口径都钉住了。

### ② 先知日历进每一屏的顶栏（`src/ui/prophetBar.ts`）

**它挂在 `windowBandHtml` 底下，不另开入口** —— 用户要的是**每一屏**都有，
而"九屏各写各的 `innerHTML`、组件靠逐个手加"正是当年窗外那条带子漏掉七屏的形状。

| 层 | 说什么 | 落点 |
| --- | --- | --- |
| 常驻那一行 | 这一场叫什么 · 今天的强度 · 还有几天 · 进度轨 · **最要紧的是哪两类** | `prophetBarHtml` 的 `.run-bar` |
| 点开之后 | 22 天的逐日强度与 `hint`（"哪几天最难"） | `prophetDetailHtml` 的 `.prophet-detail` |
| **不做** | "它上次怎么把我打倒的"（要动 `meta` schema） | — |

三条别再改回去的判据：
1. ★★ 进度轨是**倒着走**的（`--remain`：灾前七天满格 → D-Day 见底），
   方向必须与右边那句"还有 N 天"一致 —— 第一版写成了"走了多少"，被自己的用例抓住；
2. 常驻那一行**不许剧透任何一条 `hint`**（逐条 `expect(barText).not.toContain(forecast.hint)`）；
3. `toggleProphet` 里 `hidden` 与 `aria-expanded` **一起翻**（分家的表现是
   "看起来开着、读屏说关着"）。★ 它只用**属性选择器**，不许用 `#id`：
   `src/ui/fakeDom.ts` 的 `parseSelector` 不认识 `#`，`querySelector('#…')`
   在假体上永远返回 null，表现是"点了没反应"而两边都不报错。

★ **展开状态不落盘、不进 `RunState`**（§4A：界面状态永远可由存档推导），
由 `src/main.ts` 的全局事件委托调 `toggleProphet`（挂 `document` 上，屏重建时委托不会跟着没）。
★ 开局页原来那一整块强度曲线**删掉了**（它现在住在顶栏），换成"这一局会撞上什么"：
D-Day 那句 `hint` + "最要紧的是哪两类" + "你有 N 天准备" —— 选身份要看这两句。

### ③ 顺手修掉的一处真缺口：窄屏 320px 会溢出（`scripts/check-layout.mjs`）

`.run-bar-row` 里四段原来有三段写了 `flex: 0 0 auto` —— **一行里只要有一段能收缩
就不会溢出，一段都没有就会**，而溢出的东西只跑到屏幕外、**不报任何错**。
现在：`.run-bar-name` 是唯一允许收缩并省略号收尾的那段（灾难全名可以很长）、
`.run-bar-sev` 是 `flex: 0 1 auto`（**强度才该先让步，名气比它重要**）、
`.run-bar-toggle` 用 `margin-left: auto` 靠右（不靠倒计时撑 —— 开局页手里没有 `run`）。

**320px 那笔账**：可用 296px（320 − 24 内边距），固定段合计约 232px
（强度 ≈32 / 倒计时 86 / 按钮 ≈90 / 三处 gap 24），**余量约 64px**。

先量后改：三道渐变明度跨度中位 34.9 → **36.7**、**最平的一场 10.2 → 30.4**、

### ⑤ 顺手修掉的一处真缺口：点击热区原来靠运气（`scripts/check-layout.mjs`）

**这是一个"在桌面上永远看不出问题"的量**：鼠标指针只有 1px，所以桌面**任何尺寸都够**。
手机上拇指的接触面约 8~10mm，苹果给的下限是 44pt、谷歌是 48dp ——
于是"这个控件够不够大"**只能靠量**。按 `cursor: pointer` 扫出全部 **19 个有意图做成可点的类**，
逐个取 `min-height`，**12 个不够或无下限**：

| 控件 | 改前 | 改后 |
| --- | --- | --- |
| `.mini`（顶栏"怎么玩 / 图鉴"） | 36px | `var(--tap-min)` |
| `.topbar-tools .mini` | 34px | `var(--tap-min)` |
| `.swatch`（胶带色板） | 36×36px | 宽 / 高 / 下限都是 `var(--tap-min)` |
| `.tape-btn`（货架抬头那两枚） | 40px | `var(--tap-min)` |
| `.event-card .night-option` | 40px | `var(--tap-min)`（仍比 64px 那套矮一档） |
| `.codex-tab` / `.score-item` / `.boxes-fold` | 无下限（≈42 / 41 / 34px） | `var(--tap-min)` |
| `.run-bar-toggle`（展开先知日历） | 无下限（≈**23px** —— 这一行里最小的东西是它唯一的门把手） | `var(--tap-min)` |
| `.save-fold > summary`（"把这一局带走"） | 无下限（≈30px） | `var(--tap-min)` + `display:flex; align-items:center` |

★★ **最值钱的一条**：`.tape-tool`（`＋` / `✂`）与 `.tape-chip`（一张胶带）的 44px
原来**只写在 `@media (max-width: 400px)` 里**，基样式是 **34px** ——
"手机上够大"这件事当时**交给了运气**。现在宽高与下限都进基样式，媒体查询里只留 `font-size`。
新增 `:root { --tap-min: 44px }`（苹果 44pt 与谷歌 48dp 里**小的那个**）。

**守卫**（`scripts/check-layout.mjs`）三条判据，缺一条就等于没守：
① `--tap-min` 必须在 `:root` 里且 ≥ 44px（它一被调小，所有"够大"的断言会在**同一次改动里**一起变假）；
② 表里 16 个控件**至少有一条规则**写着够大的 `min-height`（一个控件往往有好几条规则，
要求条条都写是做不到的）；③ **表外的可点类必须不存在** —— 新加一个 32px 的按钮必须当场判红，
而"新加一个控件"正是这件事唯一会再次发生的途径。
★ 守卫自己踩过一次坑并因此多长了一条自证：取样正则多转义了一层（`[\\w-]` 写成 `[\\\\w-]`），
于是**一个类名都取不到**，而报出来的却是"每一行控件都没写下限"——
看上去像样式表错了。现在多一条**取样器自证**：表里每个控件都必须在真样式表里取到至少一条规则，
取不到就直说"是取样器坏了，别照着这份报告改 CSS"。

### 这一批的纪律（复用它们比重写便宜）

- ★★ **活例一个字节的新几何都不写**：示例直接复用整理页那一套类名
  （`.shelf-row` / `.row-tape` / `.row-cells` / `.slot` / `.slot-count`），
  几何靠 `style="--cols:6"`。另画一张示意图会**漂** —— 改一次格子尺寸，
  图还停在旧样子而不报错（`windowThemes` 的 `fall` 名单手抄漂了 21 场是同一种错误）。
- ★★ **点不动的东西不许做成 `<button>`**（§4A 的死按钮）；
  **说得出名字的内容要过读屏**：示例整块是 `role="img"` + 一句把画面说完的
  `aria-label`，里面那些格子仍然是 `aria-hidden`（它们是这张图的像素，不是控件）。⚠ 图注与
  `aria-label` 说的是同一件事，两处都要改就别只改一处。
- ★ **引导只在开局页出现一次、而且不是弹窗**（§5「整理期完全静默」的边界）——
  它说的一律是**通用玩法**，116 个灾难名一个都不许出现
  （开局页有一条"热浪局不许出现寒潮"的整页断言）。
- ★★ **存档导入唯一不可退让的约束**：读不出来的输入绝不能触发导入
  （导入会覆盖现成那一局，写盘之后没有回收站）。所以导入按钮一开始就是禁用的，
  只有"看一看"验过才放行；而且写进去的是**验过的那一段**，不是此刻框里的内容。
- ★ **导入 = 写盘 + 刷新**，不是就地换 store：一局的东西散在三处
  （store 内存 / 整理会话里"手里捏着的那件" / 各屏已画好的 DOM），
  就地替换只换第一处 —— 那是"看起来成功了、玩起来处处不对"的形状。
- ★ **结局那一页只画纸与格子，一个数字都不写**：撑过几天上面已经说过，
  再说一遍就是两张账（§10.1A 欠账①：非数字表达 ≠ 把数字再抄一遍）。
- ★★ 假 DOM 的两条边界（**踩过，别再踩**）：`dispatch` **不冒泡**（事件要派发到
  挂委托的那一层，被点的元素放进 `event.target`；直接 `el.dispatch('click')`
  不会触发任何东西**而且不报错**）；布尔属性在假体里记成**空串**而不是 `undefined`。
- ★★★ **整套测试环境里只装了 `HTMLElement` 一个构造器** ——
  `x instanceof HTMLTextAreaElement` 在测试里**恒为 false**，不是抛异常，
  是静默判成"这不是输入框"，于是功能在测试里走出去了、但什么都没做
  （真浏览器里一切正常）→ **测试变成验空气**。一律按标签名判（`isTag`）。
  ⚠ `src/ui/zoneSheet.ts:83` 还是 `instanceof`，它现在能过只是因为它的测试走的是另一条路。

## 7. M5 明确**不做**的（留档，免得下次审查重新讨论一遍）

- **不重做交互手感**：M0~M2 那一轮（拖拽六条根因 + `touch-action` 三次结论）已经到位，
  M5 动的是**看**与**上手**，不是**摸**；
- **不加新灾难 / 新物资 / 新事件来"撑"视觉**：视觉重构的成败与内容量无关，
  116 场已经足够验"这一场看起来是不是这一场"；
- **不给"电"和"物资尺寸"顺手造一套机制**：它们各自要先有一个设计答案（§5）；
- ⚠ **不做真锯齿的撕口**：它要两层遮罩（`mask-composite`），而它有两处**静默**出错的
  法子（写漏"盖住"那个色标 → 整张日历只剩一条纸边；`source-in` / `intersect` 写混 →
  整张纸都是斜条纹）。现在的毛边是一条标准 `linear-gradient`，读得出"这张纸的下缘磨掉了"。
  真锯齿留给将来那一版 —— **那时必须先在真机上验一次**。
