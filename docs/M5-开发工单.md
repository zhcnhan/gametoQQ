> **这份文件是"M5 现在做什么"。** 分工没变：策划案是玩法真相、
> `囤货末世-开发纪律.md` 是工程怎么做、`囤货末世-实施记录.md` 是"做到哪儿了"、
> `M4-开发工单.md` 是上一批。
>
> ★★ **2026-10 整份重写，上一版作废。** 作废的理由不是它写错了，而是
> **它的排序被真机推翻了**：上一版把"手机手感"放在第三档，写着"验一下就行、代价零"；

## 3. 已做完（只留结论与"别改回去"的判据）

### 3.1 手机可用性（2026-10，一整轮真机反馈）

**① 滑动方向 —— 真凶是一个符号**（提交 `aeac67b`）

我读了三轮代码、改了三次"到底谁在滚"，全错。真正的原因是一行：

```ts
scrollTop = before + fingerDelta;   // ✗ 手指往下划，scrollTop 该变小
```

跟手的定义（与实现无关）：**手指往下 → 内容跟着往下 → 看到上面的东西 → `scrollTop` 变小。**

- 现在全仓**只有一处写 `scrollTop`**：`src/ui/drag.ts` 的 `applyFingerScroll()`，
  `scrollTop = before - fingerDelta`；`scripts/check-style.mjs` 第 ⑧ 条守两条：
  "唯一写点"与"必须是减号"。
- ★★ **判据不许从实现里推**（我推了三次，三次都与实现一起错）。
  唯一裁判是原生对照块：`scripts/_probe-scroll-two-writers.ts` 在落点旁边建一个
  没有任何手势绑定的原生滚动块，**同一坐标、同一发手势**，两边位移符号必须相同。
  实测 6/6 同向（货架上 / 空白处 / 纸箱上 × 上下划）。
- 收尾证据：用户在真机上确认「好了，你已经修好了」（m16633）。

**② 纸箱那一叠（同一批）**

它曾经**两边都不管**：`.box` 是 `touch-action: none`（浏览器不滚），
而手势层因为"全屏只许有一个滚动容器"拿不到 `scrollHost`（我们也不滚）→
落在箱子上的竖划既不滚也不拖。现在 `src/ui/OrganizeScreen.ts` 的 `.dock-boxes`
拿回 `data-scroll-host`，滚动归我们这一层，从箱子里拖东西照旧能用。

**③ `touch-action` 的定稿（四次结论，别再试第五次）**

> **同一块像素上，同一时刻只允许有一层逻辑。**

| 写法 | 代价（都实测过） |
| --- | --- |
| `auto` | 每 6px 一次 `pointercancel`，拖拽被打断 |
| `manipulation` | 长按计时器还活着，冒幽灵 |
| `pan-y` | 浏览器接管纵向手势 → **"从箱子里拖一件出来"当场被收掉** |
| **`none` + 自己滚** | 定稿。代价：惯性得自己写（`INERTIA_TAU_MS = 400`） |

★ 定稿还包含一条**减法**：摘掉 `-webkit-overflow-scrolling: touch`。
两层同时存在过一次 —— 那次的教训不是"自己滚"错了，是"自己滚 **+** 合成器"错了。

**④ 顶栏收窄：房间 254 → 345px（424×790）**

用户口径：「把这一部分整体缩小一些…**但是各自还是要分隔开**，不要彼此叠在一起」——
所以只收空白与字号，**一条分隔线都没去掉**：

| 块 | 改前 → 改后 |
| --- | --- |
| 标题行 | 60 → **45** |
| 四格台账 | 48 → **44** |
| 窗外带子 | 34 → **30** |
| 先知栏 | 88 → **54** |
| 胶带那一行 | 47 → **44** |

- ⚠ `:root { --tap-min: 44px }`（`src/style.css:52`）是**硬地板**：
  苹果 44pt 与谷歌 48dp 里小的那个，`scripts/check-layout.mjs` 的量表守着 16 个控件。
  **四格台账（`.score-item`）本身就是按钮 —— 它不能再矮。**
- ⚠ `.window-band` 的 **30px 是下限**：`::after` 那条地平线占 18px，再矮就变成一条色块。
- ⚠ 短屏要覆盖后段的基样式时，规则必须写在**文件末尾**那块
  `@media (max-height: 880px)` 里（基样式在后面，写在前半段会**静默不生效**）。

**⑤ 那条进度轨整条删掉**（提交 `453c239`）

它是一条 4px 的倒计时横条，开局满格时是一条看不出在量什么的实心黑。
我先把它"切成一格一天"，用户的回答是：

> 「我的意思是不管那个是什么你直接给我删了」（m17059）

结论写进代码与本文档：**一个要解释才看得懂的东西，本身就是噪声。**
`src/ui/prophetBar.test.ts` 钉着"不许再长回来"（含 `--remain` / `--ticks`）。

**⑥ 屏上诊断 + 点名**（提交 `f65e051`，用户点名要的"检测"）

手机上没有 devtools，所以把"这一块是谁画的"搬到屏幕上：

- 点顶栏那条窗外带子 → 顶部展开面板，里面是**视口 / dpr / 逐块高度 /
  最近一次滚动的指纹**（`滚动 ✓ 跟手　手指 ↓160 · scrollTop −160`）；
- 面板底部「点名」打开后**点哪报哪**，报出源码位置
  （`section.run-bar → ui/prophetBar.ts:150 · style.css:4825`）——
  位置是**现扫源码**得到的，不是手抄的名单；
- ★ DEV 专用：`src/ui/layoutHud.ts` 由 `src/main.ts` 的 `import.meta.env.DEV`
  分支**动态 import**（静态 import 会把调试物打进生产包），样式全内联
  —— 一个诊断不该改产品样式表、也不该被版面守卫管着；
- ★ 顺带放行了 DEV 下的右键菜单（原来被自己的 `contextmenu` 守卫挡住了，
  于是"右键 → 检查"这条最自然的路被我堵死）。

### 3.2 视觉：D-33 整体视觉重构 + 先知日历进顶栏（做完了）

> **底色说家族（7 类）、窗外说这一场（116 个 key）、日历说时间。**

实现顺序（**先量 → 再改 `:root` → 复验三档层次 → 最后才动日历**；日历与配色互不依赖）：

- 家族底由 `src/ui/Router.ts` 的 `applyTone()` 写进 `<body>` 的**内联变量**：

  那份表没有第二个读者却会被抄错；
- **三档跨度 13.8**（`src/data/familyTone.test.ts` 9 条守着"以后不许漂回去"）；
  墨最差 **11.31** / ink-70 **4.75** / 朱红 **4.20**；七个家族色相离朱红全部 ≥ 25°；
- 116 组窗外配色**不重调**，只把那批"太像"的拉开（提交 `4869848`；
  `src/data/windowThemes.test.ts` 四条守卫：跨度 ≥ 26、饱和度 ≥ 14、不许两场同色、家族内 ≥ 3 种色）；
- ★★ **"逐场一个页面底色"被实测否决，别再回头试**：116 场里同家族有 15~25 场，
  硬凑只有"拉饱和度"（正文当场读不了）或"手写 116 个色值"，
  换来的区分度低于窗外那条带子本来就有的 —— **同家族两场的底色完全相同是刻意的**；
- 先知日历挂在 `windowBandHtml` 底下，**不另开入口**：用户要的是每一屏都有，
  而"九屏各写各的 `innerHTML`、组件靠逐个手加"正是当年窗外那条带子漏掉七屏的形状。

## 8. M5 明确**不做**的（留档，免得下次审查重新讨论一遍）

- **不再以任何形式加回那条进度轨**（含 `--remain` / `--ticks`）；
